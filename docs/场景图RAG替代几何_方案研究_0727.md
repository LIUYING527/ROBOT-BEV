> 用户提出的方向：用 3D Scene Graph 作 RAG 挂载，替代目前手搓的几何定位部分。
> 依据 = 知识库两篇论文（0724添加）：ConceptGraphs + OpenFunGraph。本文=查证后的核实版+落地映射。

## 一、两篇论文查证（修正笔记中的错误）

| | ConceptGraphs | OpenFunGraph |
|---|---|---|
| 发表 | **ICRA 2024**（arXiv 2309.16650）⚠笔记写"CVPR 2025"有误 | CVPR 2025 **Highlight**（arXiv 2503.19199） |
| 输入 | posed RGB-D 序列 | posed RGB-D 序列 |
| 节点 | 物体级（SAM类无关分割→多视角几何+CLIP相似度融合成3D节点） | 分层级：粗物体（RAM++打标+GroundingDINO检测）→细粒度交互元素（GPT-4推理"door.handle"式部件prompt二次检测） |
| 语义 | LLaVA逐节点caption + CLIP嵌入 | LLaVA多视角caption→GPT-4综合 |
| 边 | GPT-4判空间谓词（on/near/in） | 顺序功能关系推理：先局部（柜门-把手）后远程（灯-开关） |
| 卖点 | 紧凑物体中心记忆，开集查询，LLM可直接在图上规划 | 首次定义"功能3D场景图"：东西"能干什么"、谁控制谁 |
| 代码 | github.com/concept-graphs/concept-graphs（官方，README已读） | openfungraph.github.io（官方） |

已知局限（论文/社区自承认）：LLaVA-7B对小物体caption会幻觉；多视角冗余检测产生重复节点；GPT-4调用成本高。

两个方法的标准输入都是 **posed RGB-D 序列**，我们手里现成：
- **110744s2**：510帧 COLMAP注册位姿 + ZED每帧度量深度 + RGB（stride2交付版，已验证几何对齐）
- **走廊 nav_ds_real**：1314帧真图+位姿（深度在原始采集点云npz里）
不需要任何新采集。

## 四、与现有架构的咬合（关键：场景图 = 慢脑的长期空间语义记忆）

```
任务指令(自然语言) 
   → LLM/VLM 在场景图上RAG检索("白桌上的铁柜"→节点#7: caption+3D坐标+CLIP嵌入)
   → 节点坐标 → 站位计算 → 状态机导航(现有)
   → 到位后 VLM时序慢脑在线确认(现有, 0727刚建)
```

- **场景图 = 离线建成的、持久的、可查询的记忆后端**；VLM时序慢脑 = 在线感知确认。两者互补不冲突。
- `vlm_temporal_slowbrain.py` 的 `memory_text()` 可直接从场景图检索生成——长记忆从"文本日志"升级为"空间化语义图"。
- **"换prompt即换目标"机制升级**：现在是固定prompt词匹配；场景图后=开集词汇检索（CLIP相似度+LLM语义），目标可以是从没预设过的东西。
- OpenFunGraph 的功能边（"把手打开柜门"）是二期：巡检进化到操作级任务（开柜看仪表/按按钮）时用。

## 六、风险/坑（前置声明）

- 依赖重：Grounded-SAM/LLaVA 都pin老commit，env 要单建（别污染现有三环境）
- 域差：Replica/ScanNet 是家居，我们是工业实验室；RAM++/GroundingDINO 对"铁柜/显微镜/移液枪"的开集检测率要先小规模验证再全量

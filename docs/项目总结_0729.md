# 项目总结：VLM+Diffusion 双脑机器人巡检（截至 2026-07-29）

> 给项目组内部理清"我们在做什么、做到哪了"。细节见各专项文档（文末索引）。

## 1. 一句话目标

让机器人在**真实工业场景**里听懂**自然语言任务**（"去检查蓝色水泵"/"去显微镜那里"），自主导航到目标、对准、执行检查——核心是把"理解任务"和"控制运动"分成两个脑子来做。

## 2. 为什么这么做（动机）

- 巡检/指定路径任务的难点不是"走"，而是"知道去哪、到了看什么"。纯几何导航（SLAM+预标点）要人工标坐标——**用户铁律：不许手标坐标，目标必须机器人自己找**。
- 大模型（VLM）懂语义但慢、给不了精确坐标；小模型（Diffusion 策略）快但不懂任务。→ **分工**。

## 3. 总体架构：双脑 + 三件套（一直没变，0729 再次确认不动）

```
任务文本(自然语言)
   │
[慢脑 = 自研 Infinite VLM (10.0.0.18)]      ← 语义层：场景理解、目标确认、状态机编排
   │  目标位置 WHERE + 行为条件 HOW
   ▼
[快脑 = DiffusionDrive (扩散轨迹模型)]       ← 运动层：给定目标点/条件, 输出(vx,vy,wz)全向速度
   │
   ▼
[仿真环境]  3DGS皮肤(照片级FPV, 喂VLM) + 占据几何(BEV, 喂快脑/A*)
```

- **WHERE（去哪）**：场景图 RAG（0729 起）——离线把场景建成"物体级 3D 语义地图"，任务期毫秒级检索出目标坐标。替代了之前的在线手搓几何（VLM bbox+深度反投影，单扫弱）。
- **HOW（怎么走）**：A* 粗路径 + DiffusionDrive 快脑给速度 + 控制器原语（原地转/横移）+ VLM 到场确认。
- **仿真即测试台**：真实采集（ZED RGB-D+位姿）→ COLMAP → 3DGS 高斯皮肤渲染 FPV + 同源几何出占据图 → 闭环跑策略，与真实部署接口一致（BEV 点直方图 / RGB / Twist）。

## 6. 当前能力（实测，不夸大）

✅ 已验证：
- 三场景（走廊/室外/室内）仿真闭环巡检 demo，视频齐全。
- 场景图 RAG：对**有区分度的物体**（显微镜 0.50m）检索即得坐标；**词表漂移/歧义**（铁柜被叫 microwave、白桌 13 选 1）靠"VLM 精排+关系/属性消歧"兜住（0.55~0.60m）。
- 自研 VLM 的甜区明确：yes/no 确认、bbox 定位、多帧 ANY 检测；比 Qwen3.5-4B 快 4.3×、巡检召回高 18 点。
- VLM bbox 精对准：到场后把目标转进画面中心（对准由"看到的"收口，不再依赖坐标精度）。

⚠️ 能力边界（诚实）：
- 场景图几何 **per-scene**：新场景要巡逻建图一次（抽帧约 20 分钟批处理），**不是真机零样本**；真机 SLAM 位姿建图精度未验证（当前用 COLMAP 离线位姿）。
- 白桌级**空间关系消歧**（"黄桌前的白桌"）目前是属性探针，未成通用机制。
- 自研 VLM 弱项：纯文本 JSON 整理（场景图打标环节已改用确定性 RAM 多数票）、口头方位（只信 bbox）、流式不支持。
- 3DGS 皮肤 off-path 拖糊=采集天花板，只影响美观不影响判定（VLM 用真图/几何）。

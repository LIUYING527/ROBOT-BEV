## 一、架构优化分析（本周主线）

本周完成 4 项架构级改动，全部经闭环验证；架构图演进如上（离线建图带 + RAG 慢脑 + NavCmd 参数包 + 时序历史/搜索快脑）。

### 1. 快脑输入：单帧 BEV → 参数化时序历史（论文⑦，最核心 claim）

- **改动**：历史位姿 FOV 锥点 → 当前 ego 系 → γ^lag 衰减保留 → 官方 BEV 直方图；**(W 窗口, γ 衰减) 走 status[5:6] 成为条件参数**。官方代码/模型架构零改动，W=0 与旧版逐位一致。
- **为什么**：论文核心主张"多任务导航的差异本质是怎么看历史"（巡航要短窗省算力、搜索要覆盖式长历史）。本周把这个差异从"写死"变成"可调参数"，同一个快脑开始能长出不同行为。
- **证据**：探针固定观测扫 W×γ → 局部路径随 W 系统性平滑偏移（横向 +0.12→+0.47m）而目标寻求不变 = 模型真在用历史且没被历史带偏。

### 2. 慢脑→快脑接口：单点目标 → NavCmd 结构化参数包（论文⑧）

- **改动**：`NavCmd{L=模式, τ=(目标名,坐标), bearing/dist 空间提示, Φ=(W,γ,vx) 观察配置}`，每腿派发+落盘可审计；模式→观察配置集中 PHI 字典。
- **为什么**：对应论文 nav 调用签名 `nav(L,τ,Φ)`——**接口带宽决定慢脑的知识有多少能传到快脑**，"信息吸管"变"信息管道"。

### 3. 到站确认：单问 yes/no → 四段推理链 + key-frame 复核（论文⑩⑪）

- **改动**：History/Scene/Progress/Action 四段**独立**判（不串联，弱 VLM 喂回自己的话会糊），段段落盘可定位错在哪段；判 no 时回查接近过程证据帧 top3，**≥2 帧 yes 才翻案**（机器人不动，复用渲染零开销）。
- **效果**：白桌 NOT-CONFIRMED 被复核治住（Action 判 no 诚实=站位渲染溅射是真的，复核 2/3 帧 yes 翻案）→ **三站全 YES**。

### 4. 搜索行为：行为空白 → 骨架 DFS 数据 + turn-then-go 控制器（论文⑨）

- **改动**：occ 栅格→骨架→DFS 遍历+死胡同回退 GT，856 样本训出 v5 快脑；控制器改 turn-then-go（前视点在背后先原地转再平移）+ safe_vel 逃逸。
- **为什么**：最短路 GT 教不出搜索行为（论文§4.1.3）；搜索是巡检核心行为，快脑数据里曾是空白。
- **三条教训**：①少数派条件位（13%）会休眠，必须过采样；②goal=0 本身就是搜索开关，mode 位冗余；③诊断探针输入必须在分布内，否则假警报。

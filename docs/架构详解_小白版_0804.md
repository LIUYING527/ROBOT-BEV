# 系统架构与流程详解（小白版，0804）

> 给不了解这个项目的人看的版本。先用人话讲清楚每个部分是什么、为什么存在，
> 再走一遍真实任务的完整流程，最后附术语表。

---

## 0. 一句话总览

我们造了一个**会自己看、自己想、自己走的室内机器人系统**：你告诉它"去检查一下铁柜、显微镜和白桌"，它能在一个高度还原真实实验室的虚拟世界里，自己找到这些目标、走到跟前、转过来正对着它们、并用"眼睛"确认没找错。

---

## 1. 它在什么世界里活动？——数字孪生（场景资产）

机器人现在还不能直接上真机试错（撞坏了贵），所以我们先把真实实验室"搬"进电脑：

1. **采集**：人拿着相机（ZED 深度相机）在实验室里边走边拍，录了 510 段带位置信息的视频帧——每帧都知道"相机当时站在哪、朝哪看"，还知道每个像素离相机多远（深度）。
2. **重建**：用摄影测量算法（COLMAP）算出所有相机的精确站位，再用 3D 高斯泼溅（3DGS）把房间重建成一个可以从任意角度重新渲染的三维模型。可以把它理解成：**一个 110 万个会发光的小椭圆拼出来的房间**，从哪个角度看都像照片。
3. **矫正**：重建出来的房间不是完美平的——地面会有 1~3° 的起伏扭曲（算法误差）。我们做了两轮"扶平"：先把整体拧正（untwist），再针对地面残余的波浪形弯曲，给地面测出一张"高度地形图"，把每个点按地形竖直压平（0804 新做的 z 场扶平）。
4. **两份用途**：这份模型同时出两个版本——**皮肤**（负责"看起来真"，渲染出机器人看到的画面）和**骨架**（负责"撞得准"，提取地面、障碍物位置，给导航用）。改几何必须两份同步改，否则画面和碰撞对不上（这个坑踩过）。

**目标物怎么找？** 不允许人手工标坐标（用户铁律：标好的就不算机器人自己找的）。系统用 **3D 场景图**：一个视觉模型自动把房间里所有东西检测出来、按 3D 位置聚成 185 个"节点"，每个节点带上它是什么的标签（铁柜/显微镜/桌子……）。要找"铁柜"时，像搜索引擎一样检索（RAG）出对应节点的坐标。目前任务里的三个目标坐标来自深度相机的自动测量（经人目检确认全对），正面朝向是从图像里的线条实测的。

## 2. 两个"脑子"——慢脑想，快脑走

整个系统的核心设计是**双脑分工**，跟人类"先想明白再动手"一样：

### 慢脑（大脑皮层，想事的）——视觉语言模型 VLM

一个能看图说话的大模型（当前用本地 Qwen3.5-4B，自研的 Infinite VLM 服务器最近在维护）。它**不做精细运动**，只负责高层判断：

- **确认身份**：机器人到位后，慢脑看当前画面回答"你面前是不是铁柜？是/否"。
- **结构化思考**（0803 新加）：不是简单问一句，而是分四段——History（我现在在干嘛，任务上下文）→ Scene（描述画面里主体是什么）→ Progress（我方的几何数据：离目标多远、朝向差几度）→ Action（综合判断 yes/no）。四段分开问、全程留痕，哪段出错能单独定位。
- **复核机制**（0803 新加）：如果判了"不是"，不急着下结论——机器人走过来的路上每 6 帧自动存过"证据照片"，慢脑挑视角最好的 3 张重新问，至少 2 张说"是"才翻案。这治好了一个老毛病：白桌站位因为渲染瑕疵总被误判"不是"。

### 快脑（小脑，动身体的）——DiffusionDrive 扩散策略模型

一个专门学"怎么开"的神经网络，每秒做十几次决策。它看到三样东西：

1. **眼前画面**（第一人称相机图）；
2. **俯视雷达图**（BEV：把周围点云压成一张 256×256 的俯视图，哪有空地哪有障碍一目了然）；
3. **一张任务条**（status：目标在哪、该朝哪、开多快、用什么"观察策略"、什么行为模式——下面细说）。

它输出未来几秒的行驶轨迹（一串航点），机器人跟着走。

**快脑的五个版本**（每个都对应论文 Qwen-RobotNav 里的一条经验）：

| 版本 | 学了什么新本事 |
|---|---|
| v2 | 数据再平衡（别让"直行"样本淹没"转弯"样本）+ 条件 dropout（偶尔故意不给目标，学会"没目标就跟路走"，防止模型偷懒） |
| v3 | 目标连续随机采样（不是背几个固定动作，而是学会"按参数调行为"）+ 到站前减速 + 速度随机化 |
| v4 | **时序记忆**：能看到自己最近走过的 8 个位置（越远越淡忘），巡航时只看近处省算力，转向/对准时看全周围 |
| v5 | **搜索行为**：学会了"没有目标时的覆盖式探索"——沿着空地骨架走，死胡同会掉头折返。开关很巧妙：目标设成 (0,0) 就自动进入搜索模式 |

### 两脑之间怎么说话？——结构化指令包 NavCmd（0803 新加）

慢脑给快脑下指令，不是甩一个坐标完事，而是一个**参数包**：

```
nav(L=CRUISE,                    ← 模式：巡航/横移/搜索
    τ=("iron_cabinet", (x,y)),   ← 目标：叫什么、在哪
    空间提示(方位167°, 距离4.2m), ← 环境描述
    Φ=(W=2, γ=0.7, vx=0.5))      ← 观察配置：记忆窗口/衰减/速度
```

关键思想（论文最核心的主张）：**不同导航行为的本质差异是"怎么看历史"**——巡逻只要看近处，对准要看全周围，搜索要记住哪去过。把这个做成可调参数，同一个快脑就能长出不同行为。每个指令包都落盘存档，出问题可审计。

## 3. 执行层——状态机 + 安全网

真正跑任务时，一个状态机按顺序编排"腿"（每一段路程叫一腿）：

- **CRUISE 巡航**：A* 算法在俯视图上画一条避开障碍的粗路线（只当"路标"用），快脑看着路标自己开。期间每走 0.4 米就往记忆里存一个位置（供 v4 时序历史用）。
- **ALIGN 对准**：到站后不急着确认——先精确转到目标的"正脸朝向"（比如铁柜正面朝 167°），再横向平移把身子挪到正面对称轴上，三个指标全收敛（朝向差<1.5°）才算对准。
- **WAIT 等待**：停下 2 秒，慢脑做四段确认。
- **STRAFE 横移**：全向底盘可以不平移转向直接横着走（铁柜→显微镜就是横移过去的）。
- **安全网**：随时查"再往前 0.25 秒会不会贴墙"，太近就减速并朝空旷方向偏——快脑出错也撞不上。

## 4. 一次真实任务的完整流程（0803 实跑数据）

任务："从原位出发 → 去铁柜对准等待 → 横移到显微镜等待 → 去白桌等候 → 回原位"

1. **准备**（0.5 秒）：加载房间模型、算好三个站位和四条腿的粗路线。
2. **腿1 去铁柜**：慢脑派发 `nav(CRUISE, 铁柜, Φ=(W2,γ0.7))`。快脑巡航 4 米，对准后：距柜 0.73m、朝向差 0.9°。慢脑四段确认：Scene 段自己描述出"cabinet"，Action 判 yes → **一次通过**。等待 2 秒。
3. **腿2 横移到显微镜**：平移 0.76 米，对准：距离 0.79m、朝向差 1.1°。Scene："microscope" → **一次通过**。
4. **腿3 去白桌**：到位 0.97m、朝向差 0.9°。但这次 Action 判了 **no**——这个站位渲染画面确实有溅射瑕疵，慢脑没看错。触发复核：回查走近过程中的 3 张证据照片，其中 2 张（距离稍远、画面更干净的帧）判 yes → **2/3 翻案通过**。
5. **腿4 回原位**：A* 画 4 个路标，快脑开回出发点。全程 26 秒，路径 7.42 米。

**搜索模式**（0804 新验证）：不给任何目标（目标=(0,0)），快脑自己进入覆盖式探索，从房间中间一路探索到最深处 5.1 米外的角落，遇到障碍自己减速绕行。

## 5. 这周（0802-0804）改了哪里

| 改动 | 为什么 |
|---|---|
| 快脑加时序记忆（v4） | 论文最核心主张：行为差异=观察策略差异 |
| 慢脑指令改结构化参数包 | "信息吸管"变"信息管道"，慢脑的知识能完整传给快脑 |
| 慢脑确认改四段推理+复核 | 白桌误判老毛病被治住 |
| 快脑加搜索行为（v5） | "找目标"是巡检核心行为，以前数据里是空白 |
| 搜索闭环修两个 bug | 搜索循环忘了喂历史（模型拿到和训练不一样的输入）+ 控制器不会掉头 |
| 地面 z 场扶平 | 地面残余波浪弯曲，中位倾斜减半到 1.5° |
| 视频标注"正脸线" | 旧的朝向箭头在正对时退化成一条扎进地里的竖线，改成画"正面参考线" |

## 6. 术语表

| 术语 | 人话解释 |
|---|---|
| **3DGS / 高斯泼溅** | 用几十万个带颜色的小椭圆球拼出三维场景的技术，渲染快且逼真 |
| **COLMAP** | 摄影测量软件：从一堆照片反推出每张照片的拍摄位置和场景三维结构 |
| **BEV（鸟瞰图）** | 把传感器数据压成一张从上往下看的地图，机器人导航的标准输入 |
| **VLM（视觉语言模型）** | 能同时看图片和文字的大模型，比如"看图回答这是什么" |
| **慢脑/快脑** | 借自《思考，快与慢》：慢脑=大模型做高层语义决策（慢但聪明）；快脑=小神经网络做运动控制（快但只管执行） |
| **DiffusionDrive / 扩散策略** | 一种轨迹生成模型：从噪声逐步"去噪"出一条平滑行驶轨迹，本用于自动驾驶，我们迁移到机器人 |
| **RAG（检索增强生成）** | 先检索相关资料再回答的技术；这里指从场景图里检索目标节点 |
| **场景图 / 节点** | 把房间里的物体自动检测、按 3D 位置聚类成的结构化地图，每个"节点"=一个物体 |
| **A\*** | 经典寻路算法，在栅格地图上找绕开障碍物的最短路线 |
| **status / 任务条** | 喂给快脑的条件向量：目标点、朝向、速度、记忆窗口、行为模式 |
| **条件 dropout** | 训练时故意随机删掉条件信息，逼模型不依赖单一信息源 |
| **front / 正脸朝向** | 目标物体正面面对的方向（机器人应该正对着它站） |
| **untwist / z 场扶平** | 矫正重建误差的两种手段：前者整体拧正，后者把残余的地面波浪竖向压平 |
| **confirm / 确认** | 到位后慢脑判断"是不是目标"的环节 |
| **key-frame 复核** | 判"不是"时回查接近过程中存的历史画面再次判断 |
| **暖启（warm-start）** | 新版本训练从旧版本的参数出发继续练，而不是从零开始 |
| **门（gate）** | 模型里一个可学习的开关，学会"什么时候该看场景、什么时候该看指令" |
| **死胡同折返** | 搜索时走进死角自己掉头回来—— shortest-path 数据教不会的行为 |
| **sim-to-real** | 仿真训练、真机部署的迁移技术（下一步） |

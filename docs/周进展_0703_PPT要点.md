## 幻灯片 2 — 皮肤线：ArtiFixer 修好"采集物理下限"⭐重点页

- **问题**：我们单程前视采集，机器人一偏离采集线（off-path），3DGS 皮肤就拖糊——这是采集的物理天花板，普通后处理救不了。
- **做法**：NVIDIA ArtiFixer（SIGGRAPH 2026，代码权重全开）生成式扩散，专修 off-path 拖糊。**只进皮肤层**（FPV 给 VLM 看 / demo），**不进几何层**（生成=幻觉，导航几何继续用真实测量，防撞墙）。
- **本周攻克**：OOM 根因钉死（参考帧 fp32 投影撑满显存，非窗口/多卡能解）→ 正解配置 `num_views=2 / local_attn=9 / sink=5` 单卡跑通。
- **效果（实测对比帧）**：输入糊成一团（墙面拖影、控制箱鬼影）→ 输出锐利照片级（控制箱清晰、消防阀门/管路分明、地面标线整齐、墙上标牌可读）。
- **一句话结论**：**验证了生成式后处理能救视觉皮肤层**，补上几何天花板缺的观测视角。
- **素材**：
  - 对比视频：`outputs/artifixer/corrected/.../comparison.mp4`（40 帧，干净，**demo 用这条**）
  - 更长：`outputs/artifixer/corrected_long/`（80 帧）、`corrected_full/`（120 帧整条走廊）
  - ⚠️ `corrected_full` 有几处绿团鬼影 = off-path 轨迹推太狠越界穿模（我方轨迹设计问题，非 ArtiFixer 问题），演示优先用 40 帧那条。

## 幻灯片 4 — 架构端到端首次跑通（两阶段非反应式）⭐重点页

- **难点**：渲染器（discoverse_venv）和模型（需 lightning/hydra/nuplan）依赖冲突，无法同进程。
- **解法**：采用 NAVSIM 官方**非反应式两阶段**范式（预测一次 4s 轨迹→静态环境展开→评分），天然把渲染与模型解耦、绕开 env 冲突。并用极小 `_nuplan_shim` 免装整套 nuplan（装了会搞坏 ArtiFixer）。
- **数据流**：`Stage A`（渲 FPV + 存位姿）→ `Stage B`（FPV+BEV+status → DiffusionDrive → 4s 轨迹 → 占据里展开算碰撞/进度 → 出视频+指标）。
- **结果**：40 帧全程跑通、可视化正确。
- **一句话结论**：**整条架构数据流通、模型可被仿真驱动**——这是"管路通了"，不是"效果好了"。
- **诚实标注**：无碰撞率/进度数值差 = 预期内的 **domain gap**（学长 ckpt 训真实 ZED，喂它仿真的 3DGS 皮肤 + 几何 BEV 会水土不服）；真效果要重训。
- **素材**：`arch_e2e/runs/eval_nonreactive_colmapjoint_all.mp4`（左 FPV + 右 BEV 叠预测轨迹）；架构图脚本 `scripts/draw_arch.py`。

## 幻灯片 5 — 独立架构文件夹 `arch_e2e/`（工程整合）

- **做了什么**：把端到端架构整进一个**独立文件夹**，**从学长的 `robot_orig_code` 解耦**——需要的代码/权重都复制进来（`vendor/` + `weights/`），脚本里零真实外部引用。
- **自带实时更新的说明文档** `README.md`（随进展改，同 bev_gallery 风格）。
- **结构**：`pipeline/`（三阶段脚本）+ `vendor/`（navsim/官方BEV/nuplan-shim）+ `weights/`（ckpt/anchor/backbone）+ `runs/`（产物）+ `vlm/`（慢脑）。
- **一句话结论**：架构成为**自成一体、可独立演进**的模块，后续换模型/重训不牵动学长目录。

## 幻灯片 6 — VLM 慢脑：按我们的架构（区别于学长）⭐重点页

- **澄清两套接口（重要）**：
  - **学长的**：VLM → `cruise/turn/inspect/exit` 4 个**运动基元** one-hot（靠运动学启发式标）——不是语义理解。
  - **我们的**：VLM 慢脑做**语义场景/任务识别**（要场景间区分度），经**新增的任务条件注入通路**进快脑 → 从"沿路开"变"按任务选轨迹"。这是把 DiffusionDrive 从车端迁到任务驱动机器人的**论文级创新点**。
- **本周动作**：拉起 VLM 慢脑，**先只跑验证**（few-shot 不训，看它能不能区分不同巡检场景），暂不接快脑（接需按新通路重训）。
- **选型（含查证）**：定 **Qwen3.5-4B**（2026.03 原生多模态、同规模强于 Qwen3-VL、能上端侧 Orin、我们环境的 transformers 支持）。查证澄清：**没有"Qwen3.7"**；更新的 Qwen3.6 只有 27B/35B 大杯且环境不支持，故不选。
- **⭐验证结果（已通过）**：40 帧 FPV 逐帧输出，**解析 40/40，12 种任务**，区分度好且接地：
  - #20 认出"带**红色指示灯的配电柜**" → 靠近配电柜巡检；#15 管道/**阀门** → 靠近阀门查看；
  - #39 "**绿色安全出口指示灯**" → 靠近出口查看；#04/25/33 直行走廊 → 直行巡航；#00 全黑 → 暂停巡检。
  - **0617 担心的 3B 幻觉基本未现**；副产品：off-path 糊帧被判"等待画面恢复"→印证皮肤线也有用。
- **一句话结论**：**双脑的慢脑验证通过**——Qwen3.5-4B few-shot 不训即可认场景/点名设备。下一步拍板任务条件形式（离散语义集 / 语言 embedding）并重训快脑接语义条件。
- **素材**：图库 `arch_e2e/runs/vlm_slowbrain_colmapjoint_all/index.html`（逐帧图配语义判断，可截图上 PPT）。

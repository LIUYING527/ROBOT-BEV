## 1. 部署拓扑（各在哪台机器跑什么）

```
┌── Jetson Orin（真机，实时 10-30Hz）────────────────────┐    ┌── GPU服务器 10.0.0.20（异步秒级）──┐
│  robot_control_current（ROS2 Humble, systemd 12服务）  │    │  reloc_server.py :8321（GS重定位） │
│   ├ 底盘/升降/手柄/双臂（chassis_control 等）          │    │  vlm_server_local.py :8152（Qwen）│
│   ├ web_control/server.py :8080（ZED独占+录制）        │    │  或 自研VLM 10.0.0.18:8152        │
│   └ ZED 写 /dev/shm/zed_color.raw / zed_depth.raw     │    │  auto_map_pipeline.sh（离线建图） │
│  基线DiffusionDrive: robot_orig_code/infer.sh          │    │  离线: 建图/场景图/训练全在这    │
│  reloc_client.py（numpy+requests, 发点云求纠正）       │────┼──→ 10.0.0.20:8321 POST /reloc     │
│  Twist → /svtrobot_cmd（≥2Hz, 0.5s超时红线）           │    │                                  │
└─────────────────────────────────────────────────────────┘    └──────────────────────────────────┘
```

**原则**：Orin 只做必须实时的（快脑前向、控制器、安全层）；一切秒级以上的（GS 优化 ~43s、VLM ~0.5s）走 HTTP 异步，结果回来前按 believed 继续走或原地等。

## 2. 现场准备（约 0.5 小时，全部可在 Orin 上直接做）

### 2.1 开机 + 机器人系统启动

```bash
cd ~/svtrobo_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
bash src/start_all.sh        # 一键起：底盘控制 → rosbridge → Web 服务
```

**预期效果**：
- 12 个 systemd 服务进入 running（`systemctl --user list-units | grep svtrobo` 或直接看 start_all.sh 输出）。
- `ros2 topic list` 能看到 `/svtrobot_cmd`、`/chassis/cmd_feedback`、`/chassis/diagnostics`、`/chassis/joint_states`。
- Web 控制台 `http://<orin-ip>:8080` 能打开，显示底盘/电池/诊断面板。

**判据（错了就是没起来）**：`/svtrobot_cmd` 不在 topic 列表 = 底盘控制没起来，一切后续都白搭，先查 `chassis_control`。

### 2.2 网络连通（Orin ↔ GPU 服务器）

```bash
# RELOC 服务（10.0.0.20:8321）
curl -m 5 http://10.0.0.20:8321/health
# 期望: {"ok":true,"frames":<N>,"obs_scale":0.70}（N>0 说明地图已载）

# VLM 服务（自研 10.0.0.18:8152，或服务器本地 Qwen）
curl -m 5 http://10.0.0.18:8152/api/tags        # 自研VLM
curl -m 5 http://10.0.0.20:8152/health          # 本地Qwen，期望 {"status":"ok","model":"Qwen3.5-4B"}
```

**预期效果**：health 返回 `ok` 且 `frames>0`（RELOC 地图已载入）。**判据**：`curl` 超时/拒绝 = 服务器端服务没起，先在服务器上把 §3.1 的服务拉起来。

### 2.3 ZED 相机 + 采集验证

Web 控制台点「录制」录 10 秒，或直接看实时画面。

**预期效果**：前端实时显示 ZED 彩色流（约 2fps 存储 / 30fps 显示）；录制目录出现标准布局：

```
recordings/YYYY-MM-DD/HHMMSS/
├── images/zed/*.jpg          # ZED 左眼彩色（2fps）
├── depth/zed/*.jpg           # 深度 JET 着色（2fps）
├── pointcloud/zed/*.npz      # 点云 xyzrgba float16 mm（~2fps，全分辨率）
├── rosbag/*.db3 → *.jsonl
├── imu.jsonl / summary.json
└── ...（chassis_joint_states / svtrobot_cmd / f710_joy 等 jsonl）
```

**判据**：`pointcloud/zed/*.npz` 非空且能 `np.load(...)['xyzrgba']` 读到 `(720,1280,4)` float16 mm —— 这个 npz 是后续建图和 RELOC 的**唯一度量输入**，格式错全链断。**判据**：点云单位是 mm、有深度有效点（非全 0）。

## 3. P0 冒烟（当前可执行，约 1 天）

### 3.1 服务器端：把两个 HTTP 服务拉起来

在 GPU 服务器（10.0.0.20）上：

```bash
# ① RELOC 精定位服务（常驻，吃 GS 地图）
#   ⚠ 旧 lab 图（110744s2）尺度是 0.70× 债 → OBS_SCALE=0.70
#   ⚠ 新场景重 align 后（cam_height=1.71 实测）→ OBS_SCALE=1.0
OBS_SCALE=0.70 CUDA_VISIBLE_DEVICES=4 ~/discoverse_venv/bin/python scripts/reloc_server.py --port 8321
# 期望: [server] 地图已载 colmapjoint_110744s2, obs_scale=0.70, port=8321

# ② 本地 Qwen VLM 服务（自研 10.0.0.18 不在线时的替代）
CUDA_VISIBLE_DEVICES=3 /home/DongBaorong/micromamba/envs/artifixer/bin/python scripts/vlm_server_local.py --port 8152
# 期望: [vlm] 服务启动 http://127.0.0.1:8152
```

**判据**：`curl http://10.0.0.20:8321/health` 返回 `frames>0`；`curl http://10.0.0.20:8152/health` 返回 `ok`。

### 3.2 基线 DiffusionDrive 干跑（`--dry-run` 只打印不发指令）

在 Orin 上（`robot_orig_code` 目录）：

```bash
bash infer.sh     # 已配 --dry-run + 限速(max-vx 0.1 / max-wz 0.05)
```

**预期效果**：策略节点加载 `best-val-loss.ckpt`，读 `/dev/shm/zed_color.raw`+`zed_depth.raw`，每步打印 8 位姿轨迹 + 4 模式头决策（cruise/turn/inspect/exit），**但不发 Twist**、底盘不动。

**判据**：
- 无 CUDA OOM、无 ZED shm 超时（shm 超过 3s 不新鲜会自动 POST 重启相机，若反复出现 = 相机没起来）。
- 打印的轨迹数值量级合理（x 前进米级、y 横向亚米级），不是 NaN/全 0。
- 这是验证「特征构造链路 + 模型加载 + 控制环」三段是否通的地基测试。

### 3.3 RELOC 三级冒烟（真 zed 重定位精度，真机前必过）

详见 `真机RELOC_冒烟runbook_0811.md`。核心三级：

**A 级 · 重复性**：同一位置多次 POST，结果一致
```bash
# 在 Orin 上（真机 live_grab）或服务器上离线 npz 测试
python scripts/reloc_client.py --x 0 --y 0 --yaw 0          # 真机取当前 zed 点云
python scripts/reloc_client.py --npz <某帧.npz> --x .. --y .. --yaw ..   # 离线回放
```

**B 级 · 收敛域**：给 believed 加扰动，看能否拉回真值
```bash
# 服务器端自测（用采集 npz + COLMAP GT 自动扰动打分，零真机风险）
CUDA_VISIBLE_DEVICES= python scripts/reloc_client.py --selftest --frames 8
# 期望: [selftest] n=8 水平中位X.Xcm p90=X.Xcm yaw中位X.XX° 接受率XX% 平均XXs/次
```

**C 级 · 物理精度**：卷尺实测对照（机器人放已知位置，POST 后对比纠正位姿 vs 卷尺量）

**预期效果 / 判据（三级的统一验收线）**：真 zed 重定位**水平 <10cm、yaw <2°**。`accepted`（loss≤0.08）率应接近 100%。

**⚠ 尺度债（0811 已定根因）**：现有 lab 图是 0.70× 世界尺度债，`reloc_server` 已用 `OBS_SCALE=0.70` 内部换算**顶着，仿真三站已验证能跑**。真机「直接跑」就用这个默认配置，**不用重 align**。要根治（真米制 + OBS_SCALE=1.0）再 `cam_height=1.71` 重 align——那是可选优化，不是今天跑起来的阻塞项。

## 8. 安全红线（真机独有，仿真没有）

1. **0.5s 指令超时自动归零**（`chassis_control.cpp`）→ 所有线程崩溃时底盘自动停车，是天然 fail-safe；但策略节点必须 ≥2Hz 持续发指令维持心跳。
2. **首次试跑一律 `--dry-run` + 限速**（max-vx 0.1 / max-wz 0.05 起步），只打印不发指令。
3. **保留深度条带急停**（0.4-0.8m 三向）作为底层，与我们的 safe_vel 叠加取更保守者。
4. **建议加 SEN0492 激光测距硬急停**（纯 GPIO 级兜底，不依赖视觉/模型）。
5. **confirm 铁律**：用真图（ZED 左眼原图），绝不用渲染图。
6. **别把 `/chassis/cmd_feedback` 当里程计**——它是指令回显非实测；真值只能靠 RELOC + 人工卷尺抽查。

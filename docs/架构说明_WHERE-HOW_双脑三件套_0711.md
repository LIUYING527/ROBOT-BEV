# 架构说明（0711 版）：双脑 + 慢脑三件套，WHERE/HOW 分离

> 接替 `架构与现状_实时.md`（0708）与 0709 的"VLM 定位左/中/右 → cond → DiffusionDrive"版。
> 本版把这几天想通的关键点固化下来：**"去哪(WHERE)"和"怎么动(HOW)"是两件事，必须分开供给；快脑对"在哪"是傻的。**

---

## 0. 一句话

> 慢脑想清楚**去哪台设备(WHERE)+要做什么(HOW)**，快脑把它变成**实时可行的轨迹**；
> 走廊直行交给 A\*，快脑的训练只花在"A\* 做不到的巡检行为(横扫/转正)"上。

---

## 1. 全链路数据流

```
                          ┌─────────────────── 慢脑 (慢, ~秒级) ───────────────────┐
   真实/仿真 FPV ─┬─▶ ① VLM 语义      : "左边那台蓝泵" / "看完了" —— WHICH + 何时结束
                  │                         │(语义, 不含坐标)
                  ├─▶ ② 检测+几何标点 : bbox → 射线打到几何 → 设备世界坐标(x,y) —— WHERE ★
                  │                         │(度量目标点)
                  └─▶ ③ 规划器+记忆    : 排序目标点 / 去重(同台不重看) / 状态机
                                            (cruise→goto设备→inspect→下一个→done)
                          └──────────────────────────┬────────────────────────────┘
                                                      │ 逐个【目标点 WHERE】(+行为意图 HOW)
                                                      ▼
   走廊推进目标点 ◀── A\*(占据图规划, 非学习) ──┐      │
                                              ▼      ▼
                          ┌──────────── 快脑 DiffusionDrive (实时, ~10-30Hz) ─────────┐
   相机特征 + BEV点云特征 ─▶  status槽[0:2]=目标点(WHERE)  →  24锚点词表打分+2步扩散去噪  │
                          │  (行为HOW通过"目标点几何"自然选中对应锚点)                    │
                          └────────────────────────────┬─────────────────────────────┘
                                                        ▼ 多模轨迹 → Top-1
                                              控制器 →(vx,vy,wz) 全向 + 避障
                                                        ▼
                                      机器人执行  仿真(现) / Jetson Orin 真机(将)
                                                        │
                                └──── 闭环: 执行后渲下一帧 FPV 回慢脑/快脑 ────┘
```

## 2. 每个模块：输入 / 输出 / 职责

| 模块 | 输入 | 输出 | 职责 | 学习? |
|---|---|---|---|---|
| ① VLM 语义 | FPV(真图最佳) | "哪台设备/看完没" bbox+语义 | **WHICH**：认得出、说得清 | 已微调(自研) |
| ② 检测+几何标点 | bbox + 相机位姿 + 几何(BEV/点云) | 设备**世界坐标(x,y)** | **WHERE**：把"那台泵"变成一个点 | 否(几何) |
| ③ 规划器+记忆 | 目标点集 + 任务状态 | 当前该去的目标点 + 行为意图 | 排序/去重/状态机 | 否(规则) |
| A\* 走廊推进 | 占据图 + start/goal | 走廊路点(前向目标点) | 直行导航 | 否 |
| 快脑 DiffusionDrive | 相机 + BEV + **目标点** | 多模轨迹 → Top-1 | **HOW**：目标点→可行轨迹 | **是(只训巡检行为)** |
| 控制器 | 轨迹路点 | (vx,vy,wz) | 全向跟踪+避障 | 否 |

**核心分工**：
- **"去哪"来自 ②检测+几何**，不来自语义。语义只说"哪一台"，坐标要靠几何投影算。
- **快脑对"在哪"是傻的**：只给它语义条件，它只会复现一段学过的运动幅度，**对不准具体设备**（这是之前"一坨/撞墙"的深层原因）。必须喂**度量目标点**。

## 3. 24 锚点的角色（快脑的"动作词表"）

DiffusionDrive 靠一套**轨迹形状词表(锚点)**打分+扩散，形状不在词表里的动作它吐不出。我们把车端 20 锚点改成 **24 条机器人尺度**：

- **20 前向扇**：直行/带弧巡航（走廊推进）
- **2 原地转**：几乎不平移只转身（**正对设备**）
- **2 纯横移**：x≈0, y=±0.85 侧滑（**沿一排泵横扫**）

**怎么被激活**：目标点(WHERE)的几何位置 + 词表，一起自动选出行为——
| 目标点在 ego 哪 | 选中的锚点 | 行为 |
|---|---|---|
| 正前方远 | 前向扇 | 巡航 |
| 就在身侧(x≈0,y大) | 横移 | 侧滑/横扫 |
| 需先转身对齐 | 原地转 | 转正对设备 |

⚠️**前提**：分类头必须被训练过"身侧目标点→横移label""要转身→原地转label"，否则后 4 条锚点永远不被选中=白加。所以训练集要混入**程序化的横扫/转正示范**（合法的动作模板，不是抄路径）。

## 4. 训练的意义边界（想清楚了）

- **走廊直行**：goal 点已把答案写脸上，GT≈朝 goal 画直线，图像/BEV 几乎用不上 → **A\* + 控制器就够，不值得训快脑**。
- **快脑训练只对三类事有意义**：①多模态避障 ②从偏离态纠回(recovery) ③**语义巡检行为(停/转正/横扫)** ← A\* 死活做不到，也是**论文卖点(语义可控多模态轨迹分布)**。
- 我们的干净 on-path 真实数据里 ①② 几乎没有 → **训练火力集中在 ③**，需要的数据是"各种设备/指令→对应巡检轨迹"，不是一路顺畅的走廊帧。

**旧 Drive 训练怎么用**：NAVSIM 预训练 / 学长真机 ckpt 都只当 **warm-start 骨干**（复用"会开车"的底层先验），不能 as-is 用（车尺度锚点/driving_command/域差/缺横移转正，直载在仿真里轨迹差是 domain gap）。

## 5. 与上一版(0709)对比：改了什么、为什么

| 维度 | 0709 旧版 | 0711 新版 | 为什么改 |
|---|---|---|---|
| 慢脑输出 | VLM 直接出**运动方式**(定位左/中/右→cond_id 9类) | VLM 只出**语义(哪台/看完没)**；WHERE 交给几何 | 语义定不了具体位置；运动方式=没有坐标→对不准设备(一坨根因) |
| "去哪" | 藏在 cond 的运动倾向里 | 独立的**度量目标点**(检测+几何) | 快脑对"在哪"是傻的，必须显式喂点 |
| 慢脑结构 | 单个 VLM | **三件套**：VLM语义 + 检测几何标点 + 规划器/记忆 | 分清 WHICH/WHERE/调度 |
| 注入通路 | cond_embed→FiLM 逐层调制 | 目标点走 **status/command 原生槽**；行为靠**锚点几何**自然选 | 用官方原生通路，不 bolt-on |
| 走廊导航 | 想让 DD "学导航" | **A\*** 负责直行，DD 不假装学导航 | 直行 DD≈A\*，训它没意义 |
| 锚点 | 车端 20(半径4~5m) | **机器人 24**(20前向+2转+2横移) | 车尺度对不上;补巡检必需的横移/转正 |
| 训练标签 GT | 扰动位姿→仿真渲 FPV→recovery 轨迹 | **真实采集图 + 真实位姿 + 相机真实走过的未来轨迹** | 渲染有域差+扰动把机器人塞进墙(19%贴墙/6%对墙)+L形横跳 |

## 一、架构一步步改造（演进脉络）

核心系统一直是**双脑**：VLM 慢脑（语义/决策，秒级）+ DiffusionDrive 快脑（轨迹生成，10–30Hz）。改造是围绕"慢脑给快脑什么、快脑该学什么"反复想通的过程。

### 阶段 0（~07-02）——整条架构先端到端跑通
- 非反应式两阶段：sim 皮肤 FPV + 官方 BEV + 位姿 → DiffusionDrive → 轨迹展开评分。
- 目的只是**验证数据流通 + 模型能被 sim 驱动**。效果差（无碰撞 0.15/进度 0.77）是预期 domain gap，不是 bug。

### 阶段 1（07-08）——语义可控性首证（cond 注入）
- 造 4 条件数据 → 接 `global_cond`（FiLM 逐层调制）→ 微调。
- **结果**：同一观测换指令 → 轨迹明显不同（cruise 直 / inspect_left 左 / inspect_right 右 / pause 停）= 可控性首证。
- 但这版把"运动方式"直接塞给 VLM（定位左/中/右 → cond_id 9 类），**埋了"对不准具体设备"的雷**。

### 阶段 2（07-11）——⭐ WHERE / HOW 分离（关键重构）
想通的一句话：**"去哪(WHERE)"和"怎么动(HOW)"是两件事，快脑对"在哪"是傻的。**

| 维度 | 旧版(0709) | 新版(0711) | 为什么改 |
|---|---|---|---|
| 慢脑输出 | VLM 直接出运动方式(cond 9 类) | VLM 只出**语义**(哪台/看完没) | 语义定不了坐标 → 对不准设备 |
| "去哪" | 藏在 cond 里 | 独立**度量目标点**(检测+几何标点) | 快脑必须显式喂点 |
| 慢脑结构 | 单个 VLM | **三件套**(VLM语义 + 检测几何标点 + 规划器/记忆) | 分清 WHICH/WHERE/调度 |
| 走廊导航 | 想让 DD 学导航 | **A\*** 负责直行，DD 不假装学导航 | 直行 DD≈A\*，训它没意义 |
| 锚点词表 | 车端 20(半径4~5m) | 机器人 **24**(20前向+2原地转+2横移) | 车尺度对不上；补巡检必需动作 |
| 训练 GT | 扰动位姿→渲染→recovery | **真实采集图 + 真实位姿 + 真实未来轨迹** | 渲染域差 + 扰动把机器人塞进墙 |

**训练意义边界**：走廊直行归 A\*（GT≈朝 goal 画直线，不值得训）；**快脑火力集中在 A\* 做不到的巡检行为**（停/转正/横扫）——这正是论文卖点。

### 阶段 3（07-11 晚）——两个"地基"根因修复
- **左偏真根因 = A\* 抄近道贴左墙**（不是 DD 模型！）。修：A\* 加离墙间隙代价 `clear_w=2.0`（cv2.distanceTransform）→ 走廊居中。同一改动**同治左偏 + 龟速**（x22.8→x33.3，同根因）。
- **统一几何**：占据栅格改用 A3D 皮肤同源几何 → 消除"FPV 撞了 BEV 没事"、A\* 贴设备走。

### 阶段 4（07-14）——⭐命令门控 gate（办法 C，可控性机制锁定）
- `CustomTransformerDecoderLayer` 加**零初始化 scene_gate**：`g=sigmoid(scene_gate(status)+4)`，`traj = g·场景特征 + (1-g)·原特征`，warm-start 无损。
- **发现真 bug**：满 240ep 同初始同数据却收敛到不同门值 → 门被 trajectory_loss 欠约束，靠随机种子运气。**修 = 固定种子 + 门正则 `gate_reg=0.3`**（平移→门开/纯旋转→门关）。
- **结果**：终门 前向 1.0 / 转向 0.0，`verify_turn_gate.png` 证 ±90° 原地转左右两向全干净。**机制成立且可复现** = 论文可控性卖点站得住。⚠️ ±45° 是 OOD 不可靠（训练 |dyaw|∈[54,90]）。

### 阶段 5（07-14~15）——巡检状态机闭环 + VLM 当项目经理
- 状态机：`CRUISE(DD沿A*) → 到设备前沿 → TURN_TO_FACE(转正) → SCAN(横扫) → TURN_BACK → 记忆记录 → 下一设备 → DONE`。
- gate 接进闭环（混合 TURN：大角度 gate-DD 原地转 + 小角度控制器收尾），4/4 设备全检视。
- **空转根因根治**：robo2vlm 逐帧 yes/no 分不清有泵/空（多选把它搞糊）→ 改 **`--geo_vlm`**（几何定在哪转 + VLM 面向 yes/no 分类是不是目标）→ 走廊 8/8 无空转。

## 二、⭐ 走廊最佳效果是怎么做出来的（完整配方）

> 最佳产物：`goalnav/runs/inspection_geovlm_0715.mp4`（几何+VLM 走廊 8/8 无空转往返巡检）。
> 底座皮肤：`gs_vggto_colmapjoint_all_684k` 系 / A3D 锐皮肤 `gs_a3d_colmapjoint_all_world_deg0.ply`。

**1) 皮肤层（视觉，喂 VLM/demo）**
- 3DGS 重建（`gs_vggto_colmapjoint_all`），SH3 + appearance 曝光建模（hqbest 配方）。
- **ArtiFixer 生成式扩散修 off-path 拖糊**（只进皮肤层，不进几何层——生成=幻觉不能拿去导航）。
- 结论：单目前视单程 = 采集物理天花板，on-path 锐、off-axis 拖丝，加高斯救不了；VLM 判定用**真图**（`RealFrameLookup` 按位姿取最近真实采集帧）故不受皮肤糊影响。

**2) 几何层（导航，喂 DiffusionDrive + A\*）**
- 占据/BEV 用 **A3D 皮肤同源几何**（`--unify_occ --occ_thr`），治 FPV/BEV 不一致。
- A\* 走廊规划 + **离墙间隙代价 `clear_w=2.0`** → 居中不贴墙（左偏/龟速根治）。

**3) 快脑 DiffusionDrive**
- 24 锚点机器人词表（20 前向 + 2 原地转 + 2 横移）。
- 命令门控 gate（正则版 `goalnav_gate.pt`）：CRUISE 给前视目标点+朝向前(1,0)；转向命令给目标点(0,0)+目标朝向(cos e,sin e) → 门关场景 → 干净原地转。
- 输入三件：`camera_feature`(FPV) + `lidar_feature_fov`(点云 FOV 直方图) + `status_gh`(目标点+目标朝向)。

**4) 慢脑 VLM（geo_vlm 模式）**
- 几何负责"在哪转 + 哪侧 + 前后沿"（坐标，VLM 不碰）。
- VLM 只做**面向 yes/no 二分类**"是不是目标设备"（真图，可靠）+ 当项目经理记进度（长时程语义，它的长处）。
- 铁律：side 只信 bbox 几何，不信 VLM 口头 left/right。

**5) 闭环状态机**：CRUISE→TURN→SCAN→TURN_BACK ×N，DD 快脑统一驱动走+转，控制器收尾小角度。

**一句话配方**：*A3D 同源几何做导航地基 + A\* 居中 + gate-DD 走转统一 + geo_vlm（几何定位置 / VLM 只做 yes/no）+ 真图喂感知* → 走廊 8/8 无空转往返巡检。

## 三、现存问题

### A. Sim-to-Real 最大缺口 = 全局位姿（0715 审计）
- sim 用环境真值位姿；真机**只有轮速里程计(≈10s 刷/漂) + IMU，无可靠全局位姿**。
- **所有吃全局位姿的部件都是迁移风险**（全是脚手架，非双脑核心）：A\* 走廊规划、巡航目标点几何、设备 x 坐标触发、扫描切向。
- 相机/点云驱动的核心部件（DD 快脑、VLM 慢脑、门控可控性）反而输入完全对齐、可迁移。

### B. 皮肤采集物理天花板
- 单目前视单程缺横向视角 → off-axis 拖丝/顶侧喷溅，358K vs 1.2M 高斯差别很小，加高斯救不了（唯一解=重采绕拍）。
- 现规避：VLM 判定用真图不受影响；但**自由漫游/大偏离视角的 demo 仍糊**。

### C. gate 的 OOD 边界
- ±90° 原地转干净可复现，但 **±45° 是 OOD 不可靠**（训练分布 |dyaw|∈[54,90]），转角 >90° 需夹到 ±π/2。

### D. 训练数据结构性偏科
- 干净 on-path 真实数据里"多模态避障 / 从偏离态纠回"几乎没有 → recovery 能力弱。
- 横扫/转正目前部分靠控制器原语 + 程序化模板，非全靠 DD 学出。

### E. 检测泛化
- 几何-only 检测（凸起聚类泛化到纯色柜子）尚未成熟；室外点云无干净周期立柱 → 检测不可靠，现用沿路等距站位兜底。

### F. 评测协议缺失
- "语义可控性"指标 + 消融链（传统/回归/w-o-VLM/完整）尚未落到 `test_env.py`，论文的量化证据还没成型。

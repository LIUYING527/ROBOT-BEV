# 真机部署方案（2026-08-19）

> 目标：把仿真中已闭环的 lab_mission 全链（慢脑VLM → NavCmd → DiffusionDrive快脑 → RELOC → ALIGN/DOCK）部署到 SVT 4WIS4WID 全向底盘 + Jetson Orin。
> 前置文档：`真机RELOC_冒烟runbook_0811.md`（RELOC三级冒烟）、`真机部署路径_场景图RAG_0729.md`（早期路径，部分过时）；机器人系统细节以 `robot_control_current/ROBOT_SYSTEM_GUIDE.md`、`SYSTEM_CONFIG.md` 为准。

---

## 0. 起点：真机上已经有什么

**DiffusionDrive 快脑已在 Orin 上实时跑通过**（`robot_orig_code/svtrobo_ws-master/src/chassis_control/scripts/run_diffusiondrive_policy.py`，2651行）：

- 纯 PyTorch fp32（无TensorRT/ONNX），加载 `best-val-loss-post.ckpt`，resnet34 backbone
- 输入：ZED左眼 resize 3×256×1024 + 深度反投影BEV 1×256×256（`bev.py points_to_bev_tensor`，±32m/4px每米）+ status 8维
- 输出：8位姿轨迹（4s horizon）+ 4模式头；BehaviorFSM 管 cruise/turn/inspect/exit
- 控制：batch模式（推理一次执行4s再重规划，loop-hz 1-2）+ spline track 20-30Hz；Twist 发 `/svtrobot_cmd`，20Hz重发
- 安全：前/左/右深度条带急停-倒车-重规划（默认0.4-0.8m）
- 观测：不独占ZED SDK，读 web server 写的 `/dev/shm/zed_color.raw`、`zed_depth.raw`（~15Hz）；shm 超3s不新鲜自动 POST 启动相机

**结论：部署不是从零开始，是在这个已验证的实时节点上换模型、换特征构造、加慢脑和RELOC。**

## 1. 硬件与接口事实表（部署约束）

| 项 | 事实 | 部署含义 |
|---|---|---|
| 计算 | Jetson Orin aarch64, L4T 5.15.185 | 快脑+控制器可上Orin（先例已证）；GS优化/VLM/建图留GPU服务器 |
| 底盘 | SVT 4WIS4WID 全向（4×RobStride舵 + 2×ZLAC8015D轮驱），控制环1kHz | 原生支持 (vx,vy,wz)，与仿真输出零差异 |
| 动作接口 | `/svtrobot_cmd` geometry_msgs/Twist：linear.x/y (m/s), angular.z (rad/s) | 我们链路输出直接可发 |
| **指令超时** | **0.5s 无新指令自动归零**（chassis_control.cpp:156） | 策略节点必须≥2Hz持续发；VLM/GS等慢调用绝不能阻塞控制环 |
| 轮速上限 | MAX_WHEEL_SPEED 100rpm，舵角变化率3rad/s，舵未到位轮速强制0 | 大角度转向天然是"先转后走"，与turn-then-go控制器一致 |
| 相机 | ZED 2i（场景相机，720p30，NEURAL深度mm，xyzrgba点云float16 mm）+ D405×2（手臂相机，不用） | 场景感知只用ZED；点云格式与仿真采集(npz xyzrgba mm)**完全一致** |
| 观测分发 | ZED由 web_control/server.py 独占；策略经 /dev/shm 或ROS2话题读 | 沿用shm先例即可，不要抢SDK |
| **里程计** | **无任何 /odom 话题**；`/chassis/cmd_feedback`是指令回显非实测；轮速实测~10s才刷一次 | 只能靠指令积分当believe（会漂）→ **RELOC周期纠偏正好对症**，这是核心卖点不是补丁 |
| 安全兜底 | 4×SEN0492激光测距（前后左右5-10Hz） | 可做独立于视觉的硬急停层 |

## 2. 部署拓扑：Orin 端 vs GPU 服务器端

```
┌── Jetson Orin（实时，10-30Hz控制环） ──────────────┐     ┌── GPU服务器 10.0.0.20（异步） ──┐
│  zed shm源 → 特征构造(BEV/相机/status)             │     │  reloc_server.py (GPU4常驻)     │
│  DiffusionDrive快脑 (PyTorch fp32, 先例2Hz)        │     │   POST /reloc: 点云+believed    │
│  turn-then-go控制器 + safe_vel + 深度条带急停      │     │   → GS渲染优化43s → Δpose       │
│  任务状态机 (移植lab_mission, 异步线程)            │────→│  VLM慢脑: 自研10.0.0.18:8152    │
│  reloc_client.py (仅numpy+requests, 已写好)        │     │   或本地Qwen3.5-4B :8152        │
│  Twist → /svtrobot_cmd (≥2Hz, 0.5s超时红线)        │     │  离线: 建图/场景图/训练全在这    │
└──────────────────────────────────────────────────┘     └─────────────────────────────────┘
```

原则：**Orin 只做必须实时的**（快脑前向、控制器、安全层）；一切秒级以上的（GS优化43s、VLM 0.5s）走HTTP异步，结果回来前机器人按believed继续走或原地等待。

## 3. 模块移植清单（逐项：在哪跑/改动点/风险）

### 3.1 离线建图（全部在GPU服务器，Orin零负担）

流程与仿真完全一致：真机zed采集（穿行走一遍）→ COLMAP → 3DGS → align → 场景图 → targets json。
- **改动点0（最重要）**：align 时 `cam_height` 用实测相机高（ZED离地~1.71m量一遍），**不要继承0.70×尺度债**；真机世界=真实米制，RELOC的OBS_SCALE应为1.0。
- 产出 targets json（站坐标+front+锚定窗）拷到Orin，只是几KB的json。

### 3.2 快脑 DiffusionDrive —— ⚠ 有两个不一致必须先解决

**(a) status 8维定义不同**：
- 真机已部署版（robot_orig）：`[模式one-hot(4), vx, vy, ax, ay]`（`task_modes.py:47-55`）
- 我们仿真版（v4/v5 ckpt）：`[goal_ego(2), head_ego, vx, hist_w/8, gamma, mode]`

两者不能混喂。两条路：
- **方案A（推荐，快）**：改真机节点的 `_build_status`（run_diffusiondrive_policy.py:1191）按我们的定义构造——goal_ego 由 believed位姿+targets json 每帧算出，hist_w/gamma 是超参常量，mode 巡航0。特征构造本来就是该节点里的Python代码，改动局部。
- **方案B（彻底，慢）**：用我们的数据配方（真图+真实未来轨迹GT，nav_ds_real式）在真机采集上重训。等方案A验证后再说。

**(b) BEV 范围不同**：真机已部署版吃 ±32m NAVSIM 直方图；我们 lab ckpt 吃局部占据窗+时序历史。同 (a) 方案A：在Orin端按 lab_mission 的 `dd_traj` 逻辑从世界ply+ believed位姿生成局部BEV窗（hist_w环形缓冲）。**风险**：Orin上每帧从百万级ply取局部窗要点优化（预载KD-tree/栅格地图，一次性把世界ply离线烘成2D占据栅格npz更稳——**推荐离线烘占据栅格**，Orin只做裁窗+时序融合，算力和test_env同源逻辑）。

其余照搬先例：fp32 PyTorch、batch或2Hz重规划、spline track 20Hz、深度条带急停保留（与我们safe_vel叠加，取更保守者）。

### 3.3 RELOC 精定位 —— 已按真机形态写好

- `reloc_server.py`（GPU服务器常驻）+ `reloc_client.py`（Orin，numpy+requests）已实现。
- Orin端把 zed 点云（xyzrgba mm→米）+believed POST 上去；server端渲染ED对比优化43s返回Δ。
- **尺度注意**：server端当前内部自动×0.70（对应旧建图债）；真机新图若尺度正确，改为1.0（server有env开关）。
- 回归头（<10ms）可以直接在Orin跑（小CNN），快路本地、慢路上服务器。
- 调用时机沿用仿真：到站必纠 + 巡航每~2m周期纠偏——**周期纠偏正好补无里程计的短板**：平时指令积分当believe（会漂），每2m被RELOC拉回真值，漂移被周期清零。
- 先跑 `docs/真机RELOC_冒烟runbook_0811.md` 的ABC三级验证再进任务链。

### 3.4 慢脑 VLM —— 纯HTTP，零移植

- Orin端就是一个HTTP客户端（requests），服务器选自研 10.0.0.18:8152（0.42-0.53s）或 GPU服务器本地Qwen。
- 四段链confirm、key-frame复核逻辑在任务状态机里（Python，随状态机一起移植）。
- **铁律保持**：confirm用真图（ZED左眼原图），绝不用渲染图。
- RAG检索在服务器离线做，Orin只拿结果（节点τ坐标）。

### 3.5 任务状态机（lab_mission.py → 真机版）

lab_mission 的编排逻辑（腿定义/状态机/ALIGN/DOCK/NavCmd）是纯Python，移植=把它的两个仿真依赖换成真机源：
1. `CorridorTestEnv.step(vx,vy,wz)` → ROS2 Twist 发布（沿用 svtrobo_controller 先例，auto_stop_timeout=0.5对齐）
2. `CaptureFPV` 渲染帧 → ZED真图；渲染ED → zed真实深度
3. believed位姿：指令积分（cmd_integrate 先例在 robot_data_prep/cmd_integrate.py）+ RELOC纠偏
4. ALIGN/DOCK 的测距：min(ED,几何) 在真机上变成 min(zed深度, 几何dist)——双源思想不变，且真机深度比渲染ED更可靠
5. **俯角**：ZED固定俯角装不下分相位云台，--pitch_cruise/-22 vs --pitch_station/-12 的差异要靠安装角折中（或加舵机云台，待定）——**这是真机独有的硬件gap，需在采建图数据时就按安装角采**。

### 3.6 安全层（真机独有红线，仿真没有）

- 0.5s指令超时 → 所有线程崩溃时底盘自动停车（天然fail-safe，但状态机要维持心跳）
- 保留先例的深度条带急停（0.4m三向）作为底层，我们的safe_vel在其上
- 建议加 SEN0492 激光测距硬急停（不依赖视觉/模型，纯GPIO级兜底）
- 首次试跑用 `infer.sh` 同款 `--dry-run`（只打印不发指令）+ 限速（max-vx 0.1/max-wz 0.05 起步）

## 5. 风险清单（按杀伤排序）

1. **status/BEV输入不一致**（§3.2）——不解决模型输出就是噪声。方案A改造后必须用同帧离线bag对比仿真特征做数值核对。
2. **无里程计漂移**——周期RELOC是对策，但两次纠偏间若漂出RELOC收敛域（±0.5m/±25°）就救不回。对策：纠偏周期从2m收紧到1m起步，实测漂移率后再放宽。
3. **网络依赖**——VLM/GS都走HTTP，断网时状态机要有降级策略（跳过confirm默认NO+key-frame复核；RELOC超时则用回归头本地快路）。
4. **俯角硬件gap**（§3.5.5）——采集、建图、targets的front检测都要按最终安装角来，先定安装角再采数据。
5. **GPU服务器被占**——reloc_server要常驻GPU4，训练任务常抢卡；服务器端加看门狗（先例：artifixer脚本的空闲等待模式）。
6. **cmd_feedback是指令回显非实测**——别把回显当里程计精度证据；真值只能靠RELOC+人工打卷尺抽查。

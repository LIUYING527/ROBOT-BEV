# VLM 慢脑 · 接口契约 + Data Sample（给 VLM 团队测试用）

> 双脑架构：**VLM 慢脑**读机器人前视图 → 输出**语义巡检任务** → **DiffusionDrive 快脑**据此生成轨迹。
> ⭐**分工铁律**：慢脑只管**语义**（该做什么任务、看到什么目标物）；**几何（往左往右、怎么走）由快脑从观测(BEV/图像)自己决定**。
> 所以 VLM **不要输出"左/右"这类方向**——那是快脑的活。本文件定义 VLM 的输入/输出契约 + 样例。

---

## 1. 任务（一句话）
输入一张机器人**前视 RGB 图**，判断此刻该执行的**语义巡检任务**，输出**结构化 JSON**。

## 2. 输入（INPUT）
- **一张前视 RGB 图**（robot first-person view）。样例来自仿真 3DGS，640×360、有运动模糊（真机为 ZED，更清晰）。
- 当前版本：**单帧 → 单决策**（暂不需要历史帧/文字指令）。

## 3. 输出（OUTPUT）—— 必须是这个 JSON
```json
{
  "task":   "直行巡航 | 靠近设备巡检 | 到达出口 | 暂停",
  "target": "巡检目标物(如 阀门/配电柜/管道/仪表/水泵); 没有则 null",
  "reason": "一句话依据"
}
```
- **`task` 唯一必填、必须四选一（照抄这四个词之一）**——这是下游快脑消费的语义条件。
- **不要有方向/左右/坐标字段**。目标在左在右、怎么绕过去，是快脑看 BEV 决定的，不归 VLM。
- `target`（目标物名）、`reason` 用于可解释/调试，尽量给。
- **只输出 JSON，不要多余文字/思考过程**。

### task 四类的判定规则
| task | 什么时候选 |
|---|---|
| `直行巡航` | 普通走廊、前方无明显巡检目标 |
| `靠近设备巡检` | 画面里有明显巡检设备(阀门/配电柜/管道/仪表/水泵…)，需要靠近查看 |
| `到达出口` | 前方是门 / 安全出口指示灯 / 走廊尽头，需驶向出口 |
| `暂停` | 画面全黑 / 严重模糊 / 无信号 / 故障，无法判断 |

## 4. 参考 prompt（可换任意 VLM，只要守上面 JSON 契约）
```
你是巡检机器人的慢脑。看这张前视相机画面, 判断此刻该执行的语义巡检任务。
只输出一个JSON: {"task":"四选一", "target":"目标物或null", "reason":"一句话依据"}
task 从这四个里选一个(照抄): 直行巡航 / 靠近设备巡检 / 到达出口 / 暂停
规则: 有阀门/配电柜/管道/仪表等设备需查看→靠近设备巡检; 前方门/出口指示灯→到达出口;
普通走廊无目标→直行巡航; 画面全黑/严重模糊/故障→暂停。
⚠️不要输出左/右/方向/坐标——目标在哪、怎么走由下游快脑决定。只输出JSON。
```

## 5. Data Sample（`samples/`）
| 输入图 | 期望 task | target |
|---|---|---|
| `sample_01_corridor.jpg` | 直行巡航 | null |
| `sample_02_cabinet.jpg` | 靠近设备巡检 | 配电柜 |
| `sample_03_valves.jpg` | 靠近设备巡检 | 阀门/管道 |
| `sample_04_exit.jpg` | 到达出口 | 安全出口指示灯 |
| `sample_05_black.jpg` | 暂停 | null |

完整期望输出见 `samples/expected_output.json`。**评测方式**：每张图喂你们的 VLM，比对输出 `task` 是否与期望一致（`target`/`reason` 合理即可）。

## 6. 下游怎么用（背景）
`task`（语义条件）→ 喂 DiffusionDrive 快脑；快脑结合观测(BEV/图像) → 生成轨迹（**设备在左在右、怎么走，快脑自己解算**）。
所以 VLM 只要**稳定、正确地输出这 4 类语义 task**即可，几何完全不用管。测试重点 = **task 分类准确率 + JSON 格式规范**。

> 注：我们快脑当前是按旧的"左/右"条件训的，正在改成这套**语义条件**（去左右，侧别交快脑），与本契约对齐。

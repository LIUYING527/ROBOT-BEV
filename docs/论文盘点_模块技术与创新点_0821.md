## Q1. 单目还是双目？为什么不用双目数据

**结论：全管线只用左目 RGB + ZED SDK 立体深度（点云 npz 的 z 通道）。双目被"间接使用"——SDK 深度本身就是双目立体匹配产物；右目图像做过一次合训实验被证伪后弃用。**

| 数据流 | 用不用 | 证据 |
|---|---|---|
| 左目 `images/zed/*.jpg` 1280×720 | ✅ COLMAP/VGGT/3DGS 光度监督/FPV/真机推理全用它 | `reconstruct_colmap.py:71`、`train_3dgs_vggt.py:1-7`、真机 `/dev/shm/zed_color.raw` |
| 右目 `images/zed_right/*.jpg` | ❌ 仅 0626 hq5lr 实验用过一次 | PROGRESS_LOG.md:528-556 |
| SDK 深度/点云 `pointcloud/zed/*.npz`（xyzrgba mm） | ✅ 深度监督/尺度标定/BEV/RELOC/DOCK 的度量真值 | `train_3dgs_vggt.py:90-116`、`真机部署方案_0819.md:13` |
| `depth/zed/*.jpg` | ❌ 伪彩 JET 可视化，非真深度 | 数据采集规范_0707.md:92 |
| IMU | 采集存了，重建不用（真机端指令积分用） | — |

**为什么不用双目图像（有据可查，不是拍脑袋）**：
1. **0626 hq5lr 受控实验证伪**：1610 左目 + 1305 同步右目（基线反推 119.6mm=标准 ZED2）合训 2915 视角 → on-path 几乎一样、转头看侧墙两版一样糊。**12cm 基线对 off-axis 缺视角是杯水车薪**，糊的根因是单目前视单程采集天花板，加右目救不了（PROGRESS_LOG.md:554-556）。
2. **右目数据质量差**：左右目 19% 不同步（PROGRESS_LOG.md:528）。
3. **COLMAP 单相机模式**（`CameraMode.SINGLE` 共享内参）要求同一物理相机，混双目要维护两套内参。
4. 论文话术：不是"我们不会用双目"，而是**"受控实验证明短基线双目对重建质量无增益，度量信息已由 SDK 立体深度提供"**——有实验支撑的设计选择。

## Q2 & Q7. 全链每块：沿用 / 改进 / 创新（含 DiffusionDrive 改动统计）

### 块① 离线重建（ZED→位姿→3DGS→世界对齐）

| 步骤 | 沿用（现成） | 我们的改动 | 定性 |
|---|---|---|---|
| 位姿重建 | pycolmap 官方 API（extract/match/mapping）；VGGT-Ω 试过，因位姿松（~0.4m）被 COLMAP 替代 | 修 COLMAP **每图独立相机 bug**→`CameraMode.SINGLE`（330/330 注册 vs 3）；**sequential+跨段桥接对**匹配策略（O(n)，exhaustive 5-6h→30min）；单线程补匹配防 faiss SIGSEGV | 工程改进（非论文点） |
| 3DGS 训练 | **gsplat 1.5.3 官方 pip 包**（rasterization+DefaultStrategy+antialiased 开关）；SH3/appearance 思路是官方标准做法 | 训练循环自写（GitHub 连不上拿不到官方 examples）；**深度监督**（ZED 度量深度，先估全局尺度再 Huber，DEPTH_W=0.4）；**过曝遮罩**（min(RGB)>225 膨胀5，光度+深度损失双剔除）；**INIT_PLY 深度稠密初始化**；UPSAMPLE 原生分辨率机制；per-image appearance gain/bias | 参数+模块级改进（"深度监督消针球"是关键效果来源，但方法本身非首创） |
| 世界对齐 | gaussian_renderer.transform_gaussian（gs_playground, MIT） | **align_gs_world 全文件自写**：cam_height 米制锚定、RANSAC 地面、--crop 裁 floater、**--untwist 逐段修 SfM roll 漂移**（11.7°→3.3°）、apply_zlevel z 场扶平（3.2°→1.5°） | 工程创新（可写进系统章节，不作核心 claim） |

**诚实标注**：重建链的定位 = "工程管线贡献"，论文里作为 system pipeline 一节，不当算法创新。已知债：世界尺度 0.70×（cam_height 假设错），真机新场景必须用实测相机高。

### 块② 快脑 DiffusionDrive（论文 60% 主体，改动统计：新机制 7 / 模块级 8 / 配置级 6）

**版本谱系**（重要，别搞混功劳归属）：官方 NAVSIM 版 → 学长上车版（4 模式 one-hot 进 status + ModeHead，**非我们的改动**）→ 我们版（与 pristine 的 diff 只 4 块：cond_embed/goal_mlp/scene_gate/norm_odo + status 语义重定义 + 时序历史）。

**新机制（7 项，论文创claim素材）**：
1. **cond_embed 语义条件注入**：`nn.Embedding(12,256)` 零初始化→time_embed→每层 FiLM 调制，warm-start 逐位无损（transfuser_model_v2.py:473-503,541,598）
2. **goal_mlp 目标方向注入**：ego 目标方向→MLP→time_embed（:478-481）
3. **scene_gate 命令门控场景**：零初始化门 g=sigmoid(·+4)，转向 g→0.046/前进 g→0.96（:337-364）+ **gate_reg 门正则**锁设计意图（train_goalnav_gate.py:29-56）——"只转向时关场景"是精确学到的可控性机制，论文最漂亮的机制证据
4. **W/γ 时序历史 BEV**：点级 γ^lag 衰减融合+位姿环形缓冲，官方直方图零改动、W=0 与旧版逐位一致（stage_b_eval.py:119-154；lab_mission.py:270-282）——"观察策略参数化"核心 claim
5. **骨架 DFS 搜索数据**：occ 自由空间 skeletonize→随机 DFS（死胡同回退 GT），856 样本教 A* 教不出的折返行为；goal=0 即搜索开关（gen_nav_dataset_lab_v5.py）
6. **NavCmd 结构化参数包**：{L, τ, Φ=(W,γ,vx)} 慢脑→快脑契约（lab_mission.py:107-130）——接口带宽是卖点
7. **数据配方**：真实轨迹 GT（非模板）、减速段前疏后密二次重采样、vx~U(0.3,0.8) 增广、直线再平衡+条件 dropout+少数派×3 过采样、镜像增广治左偏

**模块级（8 项）**：norm_odo 机器人尺度（x∈[-0.5,5]/y∈[-1.5,1.5]，3m 轨迹在车尺度下被扩散噪声淹没）、BEV FOV110° 前向锥裁点（模拟单 ZED 替代 360° LiDAR）、traj_to_control 全向 (vx,vy,wz)（官方无 vy）、turn_wz 混合转向（±45° 是 OOD）、A* 衔接（A* 只给前视点，轨迹归 DD）、status 8 维语义重定义 [goal2|heading2|vx|W|γ|mode]、锚点缩放+24 锚（+原地转+横移）、冻结策略（只训 traj_head+status_encoding）。

**配置级（6 项）**：warm-start NAVSIM ckpt、锚点 ×0.1、分域 scales json（lab 1.56m/corridor 3.49m/NAVSIM 32m）、辅助监督开关沿用、固定种子、stride。

**⚠ 写作纪律**：BEV 范围 **仍 ±32m 没改**（"改 4~6m"只是代码注释 TODO，未执行）——论文勿声称改了 BEV 范围。loss 演进链 v1 0.440→v3 0.327→v4 0.272（门 1.0/0.0）。

### 块④ RELOC 精定位（论文 20%）

**全部自研，无沿用组件**：回归头（CNN 2ch 深度+mask+pose4→Δ，<10ms，v4 双域 42.7k 样本）+ **双闸门**（步长闸门 + 纠正位姿单帧渲染验证 loss 闸门，防溅射区假接收）+ GS 渲染优化兜底（可微 gsplat，Adam+Charbonnier+IRLS coarse-to-fine，43s）+ **周期纠偏**（巡航每 ~2m odom_checkpoint，smooth slew 渐进施加——**无 odom 真机 motivation 正是卖点**）+ OBS_SCALE=0.70 尺度换算。实测：真 zed 24 帧收敛域 ±0.5m/±25°、水平中位 5.6cm、yaw 1.08°。

## Q3. 对照 baseline/benchmark 的创新性评估（接三轮对抗验证调研）

**论文级判断：三块创新在已核实的文献版图中均有空位，组合（语义可控扩散快脑 + RELOC 周期纠偏 + 真机全链）无竞品。**

| 我们的创新 | 最近 baseline（已核实） | 差异与空位 |
|---|---|---|
| 语义可控扩散快脑（cond_embed/scene_gate/NavCmd Φ） | DualVLN（双系统但无语义可控机制）、VLingNav（VLA 非扩散）、NaviDiffusor（推理期代价引导 vs 我们训练期条件，正交互补） | **"同目标换语义条件→轨迹分布变"在任何主流 benchmark 未被量化**（CALVIN/Diffusion-ES 只报成功率）→ 我们自建协议=空白填充（协议骨架见调研文档 §三：ControlNet++ 式条件回读+P/R 分布散度+ICML2025 sanity checks） |
| 观察策略参数化（W/γ 时序 BEV） | 官方 DiffusionDrive 无；导航界时序历史多为 RNN/Transformer 隐状态 | 点级显式融合+参数化（W,γ 暴露给慢脑调）少见，可作 ablation 点 |
| RELOC 周期纠偏闭环 | iComMa（去 matching 失败率 9%→38.5%）/iGaussian（iComMa 大扰动成功率→0%）**双重铁证 render-compare 必须小收敛域触发** | 他们全是"一次性定位"benchmark 设定；我们=**周期纠偏闭环+无 odom 真机 motivation+回归头加速+双闸门**，定位不同不撞车 |
| 精对准对接（min(ED,几何)伺服） | 该赛道无公认学习类 SOTA（0819 调研） | 厘米级对接+RELOC 组合在导航圈稀缺 |
| 骨架 DFS 搜索数据 | MetaNav 治"折返不果断"（0805 调研） | 教扩散模型死胡同回退的数据构造法可作小贡献 |

**Benchmark 计划**（公开轨道 GT 由仿真器提供）：
- **LHPR-VLN**（Habitat，3260 任务，当前最好 SR 仅 2.44%）——长程入场券；⚠命名：benchmark=LHPR-VLN、任务=LH-VLN；
- **GOAT-Bench**（代码开源，类别/语言/图像三模态目标，baseline SR~29.5% 未饱和）；
- 扩散快脑同口径对比：InternNav harness（NavDP/NoMaD/GNM/ViNT/iPlanner 全开源可复现）；
- RELOC 对比：iComMa 官方 repo 可跑（注意 Issue #17 自定义数据的坑）、GSVisLoc/iGaussian 引数字；⚠两篇 GSplatLoc 同名混淆勿踩；
- 真机轨道：ICRA 先例接受"仿真定量+真机定性"（NaviDiffusor，同为 Orin），我们真机有定量（卷尺协议）反而更强。

## Q4. 场景图四问（节点边界/大图vs小图/更新功能）

1. **节点边界怎么分割**：RAM 打标→GroundingDINO 框→**SAM 掩码逐帧反投影成 3D 点簇**→跨帧按点云 overlap+CLIP 余弦增量合并（959 检测→185 节点，sim_threshold=1.2）→节点空间范围=合并点云的 **OBB**。已知病（都有记录）：SAM 掩码溢出（node130 铁柜吞扫地机 1.9×1.2m）、背景词表缺 RAM 场景词（node47 怪物）、过合并是节点错位病根（有 tight0.9 版产物）。
2. **为什么只用一个大图**：就是单个扁平 185 节点图（无边、无分层、无子图；官方 GPT-4 空间边我们没跑）。理由：18×12m 单房间场景，CLIP 指纹全图余弦扫描毫秒级够用。**这是工程足够性选择，不是方法主张**。
3. **小图/分层是不是更好**：对单房间没必要；对多房间/多楼层是必要——HOV-SG 已证明层级检索 +11.69pt（核实过）。**这正是留给场景图论文的空间**（分层+动态更新都是现成 related work 对照）。
4. **有没有更新功能**：算法内核（cfslam）本身是逐帧增量合并的，但工程上我们=**离线一次性批处理**（每场景重建，cg_prep 全量 rmtree 重来），无节点 update/delete API、无动态物体处理。DovSG（RA-L 2025，开源）做的正是动态更新 → 对照已备好。

## Q6. VLM 对比计划

- **已实测（可进论文）**：自研 Infinite VLM vs Qwen3.5-4B 同帧 263 对比——**快 4.3×（0.53s vs 2.28s）、召回 +18pt（85.0% vs 66.7%）**、决策盲走 7cm vs 32cm；全帧 1314 召回 84.5%。原始 jsonl/表/图全在 `outputs/infinite_vlm_eval/`。
- **代码现状**：统一 `/api/generate` HTTP 契约，`VLM_URL` env 切换——**加新后端成本极低**。
- **论文建议对比矩阵**（按可及性排序）：①Qwen3.5-4B（已有）②Qwen2.5-VL-7B/32B 本地（同契约，半天）③GPT-4o/Gemini API（慢脑不挑食，证明架构 VLM-agnostic）④LLaVA 系（开源对照）。LHPR-VLN 上 GLM-4v/GPT-4+NaviLLM 的 SR=0 数字（FantasyVLN 表 2，已核实）可直接引用说明"通用 VLM 直接当导航脑不行"。
- ⚠ 勿夸大：多帧时序慢脑"有能力但没接"（vlm_temporal 实验仅 demo 级）；流式=服务器不支持。

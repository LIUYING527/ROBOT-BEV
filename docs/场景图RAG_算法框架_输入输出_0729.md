# 场景图 RAG 替代手搓几何：算法目标与框架梳理（0729，给学长）

> 背景：0727 定的方向——3D 场景图作为 RAG 挂载，替代 locate_target 等手搓几何定位。
> 0728-29 已在 110744s2 实验室数据上全链跑通并完成检索冒烟。本文梳理算法目标、输入、中间状态、输出。

## 1. 算法目标

机器人接到**自然语言任务目标**（如"去显微镜那里"），需要输出该目标的**世界系 3D 坐标**，供状态机/规划器导航前往。

- 旧方案（locate_target）：在线实时算——VLM 出 bbox → 射线+深度反投影。单次观测弱、需多视角三角化补丁，且每次任务都要重算。
- 新方案（场景图 RAG）：**离线把"检测+多视角几何融合"一次做透，在线只做语义检索**。几何没有消失，而是下沉为可复用的中间资产。

## 2. 框架：输入 / 中间状态 / 输出

### 离线建图（每个场景一次）

| | 内容 |
|---|---|
| **输入** | posed RGB-D 序列（110744s2：510 帧 ZED RGB + 度量深度 + COLMAP 位姿；真机上 = ZED + SLAM/里程计位姿）。**零额外采集，复用重建数据** |
| **中间状态** | ① 逐帧开集检测：RAM 打标 + GroundingDINO 框 + SAM 掩码 + CLIP 特征（官方 generate_gsa_results）<br>② 增量融合：掩码按深度+位姿反投影，跨帧按几何重叠+CLIP 相似度合并（官方 cfslam）→ **物体级 3D 节点**：{世界系 8 角点 bbox, 点云, CLIP 1024 维特征×2, 多视角标签列表, 置信度}<br>③ 语义打标：每节点多视角标签多数票 → object_tag（原设计用 GPT-4 整理，实测 VLM 文本能力不够，**已改确定性 RAM 多数票补丁**） |
| **输出** | **场景图**：185 节点 pkl（本场景），含每个物体的 3D 位置+语义标签+检索特征 |

### 在线检索（每次任务，毫秒级）

| | 内容 |
|---|---|
| **输入** | 任务目标文本（"microscope"） |
| **中间状态** | CLIP 文本编码 → 与 185 节点特征余弦相似度排序（text_ft/clip_ft 双特征均值） |
| **输出** | top-1 节点 bbox 中心 = **目标世界系 3D 坐标** → 状态机 WHERE |

## 3. 自己写的 vs 借用官方的（回应"不能直接用得自己写"）

- **借用官方 ConceptGraphs**：检测、SAM、CLIP、增量融合主干——这些是成熟组件，没必要重造。
- **自己写的**：数据桥（cg_prep，ZED 点云→Replica 格式）、语义打标补丁（RAM 多数票 fallback，官方 GPT-4 依赖在我们环境不可用且自研 VLM 纯文本 JSON 能力实测不足）、检索器（cg_rag_query.py，CLIP 相似度+双特征融合）、以及即将做的状态机接口。
- 即：**主干用官方，语义层和接口层已经是自研**，后续消歧（空间关系）也是自研。

## 5. 跨场景部署性（诚实评估）

- 语义层（RAM/CLIP 开集）：**场景无关**，换场景换目标词即用。
- 几何层（场景图）：**per-scene**，新场景必须重建一次图（机器人巡逻采集 → 建图管线；可抽帧压缩到 ~20 分钟，或在线增量边建边用）。
- 真机待验证风险：SLAM 位姿漂移 → 节点坐标误差（本次用 COLMAP 精修位姿，真机无此条件）。

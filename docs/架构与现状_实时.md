## 0. 一句话现状
双脑架构已**端到端跑通并证明语义可控**（07-08）：VLM 慢脑出语义条件 `cond_id` → 注入 DiffusionDrive 快脑（`cond_embed`→每层 FiLM）→ 微调后**同一观测换条件→轨迹分布变**（`arch_e2e/runs/controllability_colmapjoint_all.png`，见 §9）。仍是 sim + 小规模，下一步加数据/接 VLM 前端/上真机。

## 1. novelty 定位（调研 0708 定档）
通用"VLM慢脑+Diffusion快脑"架构已被 DualVLN(ICLR2026) 占死；脊柱改卖 **"度量并实现语义可控的多模态轨迹分布"**。竞品五格全空＝我们的焊缝：①语义可控性评测 ②多模态多样性度量 ③语言级条件注入 ④BEV/占据图输入 ⑤巡检真车 sim-to-real。（详见 `docs/调研_VLM-Diffusion_novelty与SOTA_0708.md`）

## 2. 整体双脑架构图
**一句话**：VLM 慢脑(2Hz)从前视图读出「语义条件」，DiffusionDrive 快脑(~30Hz)据此条件生成轨迹分布——**换条件→换轨迹分布**是核心机制。慢脑管"想做什么"，快脑管"怎么走"。

```
 每帧观测 obs
   ├─ FPV 前视 RGB  (3DGS 皮肤渲染 / 上车=ZED)
   └─ pose (x,y,yaw) ──► 局部几何(占据/点云, 导航底座)

 ┌─────────── 语义支路(慢脑) ───────────┐   ┌────── 相机支路 ──────┐  ┌────── BEV 支路 ──────┐
 │ VLM 慢脑 @2Hz  Qwen3.5-4B            │   │ FPV → resize        │  │ 几何+pose →          │
 │ FPV → 语义JSON {scene,task,objects}  │   │  256×1024           │  │ 官方 points_to_bev_  │
 │   → 语义条件 cond_id ∈               │   │ → camera_feature    │  │ tensor(前向FOV裁)    │
 │   {cruise,inspect_left,             │   │  [1,3,256,1024]     │  │ → lidar_feature      │
 │    inspect_right,pause}             │   │                     │  │  [1,1,256,256]       │
 └──────────────┬──────────────────────┘   └──────────┬──────────┘  └──────────┬───────────┘
        cond_id │                                     │ 相机               │ BEV
                ▼                                     ▼                    ▼
 ┌──────────────────────── DiffusionDrive 快脑  V2TransfuserModel ──────────────────────────┐
 │ ① Backbone(ResNet34+Transfuser) 融合 相机+BEV → BEV特征 + ego/agent query                 │
 │ ② TrajectoryHead = anchored truncated diffusion                                          │
 │     · 20 个【机器人尺度】锚点 robot_anchors + DDIM 截断去噪(2步)                           │
 │     · 2 层扩散解码器, 每层: cross-attn(BEV/agent/ego) + FiLM 调制(ModulationLayer)         │
 │  ⭐语义注入(我们的接缝): cond_id → 零初始化 cond_embed → 加进 time_embed                    │
 │     → time_embed 流进【每一层】FiLM → 逐层调制轨迹特征 → 条件真正控制轨迹                   │
 │     (零初始化: 未微调时输出=原ckpt; 微调后学出 per-condition 轨迹)                          │
 │ ③ 输出 多模态轨迹 (20 mode × 8路点(x,y,yaw), 未来4s) + 每条打分                            │
 └───────────────────────────────────────┬──────────────────────────────────────────────────┘
                                          │ argmax 选最高分 1 条(或取分布做可控性度量)
                              轨迹 → 样条跟踪(带反馈) → (vx, vy, wz) → 上车 /svtrobot_cmd
```
**控制的两根轴**（cond 给快脑的"手柄"）：横向 = inspect_left / cruise / inspect_right（左/直/右），纵向 = cruise / pause（走/停）。
**为什么这样接**：`time_embed` 本就流进每层解码器的 FiLM(`ModulationLayer`)，所以只要把条件加到 `time_embed`，**全层都被条件调制**，不用改动解码器结构；零初始化 `cond_embed` 保证 warm-start 与原 ckpt 一致。代码在 `arch_e2e/vendor/.../transfuser_model_v2.py`。

## 3. 三环境分工 + 数据流管线（为什么分两阶段）
渲染环境和模型环境依赖冲突（renderer 的 CUDA/EGL vs lightning/nuplan/VLM），**同进程装不下**；而 NAVSIM 官方本就是**非反应式**（预测一次4s轨迹→静态环境展开算分），所以**两阶段解耦**天然合规、绕开冲突：
```
【discoverse_venv】3DGS渲染(EGL)           【artifixer env】模型+VLM(同进程)
──────────────────────────────           ──────────────────────────────────
Stage A  stage_a_gen_obs.py       落盘     Stage B  stage_b_eval.py [--use_vlm]
 沿参考轨迹渲 FPV + 存 pose      ────────►   读obs → VLM慢脑 + DiffusionDrive快脑
 → runs/obs_seq_<s>/{NNN.jpg,     obs_seq   → 轨迹 → 静态占据展开算PDMS
   poses.npz}                              → 出 eval_fullchain_<s>.{mp4,json}
```
> VLM(Qwen3.5-4B ~9G) 与 DiffusionDrive 都在 artifixer，**能同进程串**；只有渲染必须分离。

## 4. VLM→DiffusionDrive 接缝（关键，已做通）
- **✅ 接法**：语义条件 `cond_id` → **零初始化 `cond_embed`**(`TrajectoryHead`) → 加到 `time_embed` → 因 time_embed 本就流进**每层扩散解码器的 FiLM(`ModulationLayer`)** → 微调后快脑学会"换条件→换轨迹"。代码在 `arch_e2e/vendor/.../transfuser_model_v2.py`。
- **⚠️ 条件集要从"几何"改成"语义"（07-08 发现的不匹配，待重训）**：
  - **当前已训模型**用的是**几何转向条件** `cruise / inspect_left / inspect_right / pause`（左/直/右/停）——这其实**不是"语义"**，而且把"往哪拐"塞进了慢脑，违背双脑分工。
  - **目标（正确的语义条件集）**：`直行巡航 / 靠近设备巡检 / 到达出口 / 暂停`——**去掉左右**，慢脑只给语义任务，**侧别/几何由快脑从观测(BEV/图像)自己解算**。这才对得上"语义可控"卖点。
  - 落地：需**设备接地的训练数据**（快脑学"看到设备就靠过去"，侧别自适应）+ **重训**。VLM 契约已按语义版给出（`docs/vlm_handoff/`）。
- **🟡 待接（VLM 前端）**：`cond_id` 现在训练/测试**直接给**；下一步 VLM 慢脑(FPV→语义 task→cond_id)接前端自动出条件（`stage_vlm_slowbrain` 已能出语义 JSON）。

### 定位（论文脊柱，07-08 讨论确定）
- **"工业巡检"不是 novelty**，是 application + motivation + 真机落点；卖点是**跟场景无关的"语义可控轨迹分布"机制** + 真机。
- 机制通用 = **强点不是弱点**：应跨场景证同一可控性（我们 sim ＋ 公开 benchmark 住宅 ＋ 真机），"generality"本身是卖点，堵"过拟合单走廊"的质疑。

## 9. Phase 2 ✅ 端到端跑通（语义可控性，sim 自建数据）
**目标**：让快脑"换语义条件→出不同轨迹"。四步（任务 #1-#4）**07-08 当天全部跑通**：造数据 → 接 global_cond → 微调 → 可控性对比图。

> **✅ 结果（07-08，已修干净）**：`arch_e2e/runs/controllability_colmapjoint_all.png` —— **微调前**4条件轨迹全缩脚下一团（不认条件）；**微调后**同一观测换条件→**4条干净平滑分明的轨迹**(cruise直/inspect_left左弯到左墙/inspect_right右弯到右墙/pause停)。**"换指令→轨迹变"＝语义可控性，端到端证明。**
> ⚠️**首版是锯齿一坨→已定位并真修**：根因＝模型 `norm_odo` 是 NAVSIM **车尺度**(x/56.9)，机器人3m轨迹归一化后挤在-0.9附近被扩散噪声淹→抖。**修法**＝`norm_odo/denorm_odo` 改机器人尺度 + `plan_anchor` 换20个机器人尺度锚点(`robot_anchors()`覆盖直/左/右/停)。重训 loss 4.88→1.6(ep5,比车锚点快得多)。仍是 sim+33位姿规模，pose#0左弯偏短，但轨迹已平滑站得住。
>
> **怎么接的（最小注入）**：`transfuser_model_v2.py`(vendored) `TrajectoryHead` 加**零初始化 `cond_embed=nn.Embedding(8,d_model)`**，`forward_train/test` 里 `time_embed += cond_embed(cond_id)`。关键洞察=**time_embed 本就流进每层 decoder 的 FiLM(`ModulationLayer`)**，故只改 time_embed 就全层被条件调制，**不用穿 decoder**；零初始化保证 warm-start 输出与原 ckpt 一致。`cond_id` 走 `features["cond_id"]`。
> **训练脚本** `arch_e2e/pipeline/train_conditional.py`(artifixer)：复用现有 obs_seq 33位姿FPV(不重渲)+ply算BEV，每位姿×4条件，冻 backbone 只训 trajectory head，扩散 loss(`targets["trajectory"]`(bs,8,3)=`make_traj`模板)。产物 `runs/cond_finetuned.pt`。

- **条件→轨迹**：ego 系(x前 y左)8 路点模板 `make_traj()`，机器人尺度。**训练直接复用现有 obs_seq 33 位姿 FPV**(不重渲)，每位姿×4条件；GT=模板。

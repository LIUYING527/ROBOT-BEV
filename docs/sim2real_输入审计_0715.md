# Sim-to-Real 输入审计（0715）

> 核心原则：**评判任何部件"好不好"之前，先问"真机上有没有这个输入"。**
> sim 里效果再好，如果依赖了真机拿不到的输入（尤其精确全局位姿），上机就是零。
> 真机输入来源 = ZED 相机（度量深度 mm + xyzrgba 点云）+ 9轴 IMU + 4轮转向轮速里程计 + `/svtrobot_cmd (vx,vy,wz)`。
> 逐行核自 `robot_control_current`（见 memory: current-robot-ws-control-capture-0707）。

## 二、关键缺口 = 位姿 / 定位

sim 里位姿是真值，真机没有。**依赖精确全局位姿的部件 = 迁移风险最高**（全是脚手架，非双脑核心）：

- **A\* 走廊规划**：需预建占据地图 + 在图上定位 → 无好位姿则不可用
- **巡航目标点几何**：`cruise_goal`、`path_tan` 用位姿算
- **设备 x 坐标触发 / 扫描切向**：用位姿

**摄像头/点云驱动的核心部件反而最能迁移**（真机有对应输入）：
- DD 快脑（相机 + 点云 → 轨迹）✅
- VLM 慢脑（相机 → 语义决策）✅
- 门控可控性机制（命令 → 轨迹分布）✅

## 三、上机前的整改清单（凡"偷用真值位姿"的都要换）

| 现在（用位姿） | 上机应改为 |
|---|---|
| A\* 全局路径给巡航点 | **VLM 从相机判巡航方向**（`--vlm_cruise`，待做）+ bev_safe 防撞。不需全局位姿/地图 |
| 检视触发按设备 x 坐标 | VLM 从相机语义触发（已是 VLM 模式的做法 ✅） |
| 转向到位、扫描切向按位姿 | 相机/点云现算局部几何，或语义驱动 |
| RealFrameLookup 按位姿取真图 | 真机直接用实时相机（无需查找）✅ |

局部相对位姿（IMU + 轮速短时积分）够用于"原地转 90°""横扫 3m"这类**短时相对**动作；不可依赖的是**长时全局**位姿。

## 四、结论

- **双脑核心（DD + VLM + 门控可控性）sim-to-real 输入完全对齐**，是可迁移的真东西。
- **风险集中在吃全局位姿的脚手架**（A\*、几何目标点）——这也是"用 VLM 替代 A\*"的真实动机（去掉位姿/地图依赖），非仅架构美观。

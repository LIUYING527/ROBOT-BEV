## A. 仿真优化（闭环测试台）

### A1 ★ BEV 洗干净 + 收窄范围（喂快脑的定版输入）
- **做什么**：从测量几何做 TSDF/log-odds 占据融合去噪 → ego 裁窗，范围从车端 ±32m 收到室内 **±4~6m**，输出 `[1,256,256]`。与 3DGS 皮肤解耦（BEV 只吃几何，不吃生成）。
- **为什么**：±32m 对室内过大、单帧直方图脏；重训快脑必须喂它最终要吃的那张 BEV。
- **产出**：`sim_bev.py` 增 `occ_bev` 通路（可复用 `clean_occgrid.py`/`fit_world_geometry.py`）；每帧 ego BEV。
- **依赖**：无（可立即做）。

### A2 ★ 底盘对齐 4WS：`(v,ω)` → `(vx,vy,wz)` omni
- **做什么**：把 pure-pursuit / 步进从差速 `(v,ω)` 扩成 omni `(vx,vy,wz)`（含横移 vy），匹配上车 SVT 4WS 抽象。
- **为什么**：上车策略输出 Twist(vx,vy,wz)、底盘是 omni；sim 不对齐则训好的策略/重训标签都错。
- **产出**：`test_env.py` 的 `step()` 支持 vy；轨迹展开用 omni 积分。
- **依赖**：无。

### A3 反应式闭环模式（补上真闭环）
- **做什么**：在非反应式两阶段之外，接一个**逐步反馈**的闭环：`obs → 模型 → (vx,vy,wz) → 步进 → 新 obs`。
- **为什么**：非反应式只验证"数据流通"；真正测策略要闭环（每步用模型输出驱动机器人）。
- **产出**：闭环 runner（`test_env.py` 已有 pure-pursuit 骨架，替换为模型驱动）。
- **依赖**：A2（omni 步进）。

### A4 皮肤接清晰 FPV（降 domain gap）
- **做什么**：闭环/评测的 FPV 改用 **ArtiFixer 修复皮肤**而非原始糊 3DGS。
  - 省事法：沿固定参考轨迹让 ArtiFixer 渲一版当 FPV（仅固定轨迹有效）。
  - 正道：**ArtiFixer3D 蒸回 3DGS/3DGRUT** → 任意位姿都清晰（闭环可用）。
- **为什么**：慢脑验证已显示 off-path 糊帧会被判"等待画面恢复"；清晰皮肤让慢脑/demo 更稳。
- **产出**：清晰 FPV 源（2D 或蒸回的 3D 资产）。
- **依赖**：ArtiFixer 线（皮肤层，独立推进）。**注意：只进皮肤层，几何/BEV 不受影响**。

### A5 可脚本化任务场景（为重训造数据）
- **做什么**：在 sim 里脚本化布置巡检场景（设备点/岔路/出口…）+ 生成**真值轨迹**（我们有真值，比学长伪里程干净）。
- **为什么**：重训快脑要标准 `.npz`（image_u8 / lidar_feature / trajectory(ego) / status / task）。
- **产出**：数据生成器（对齐 `run_preprocess.py` 的 9 键契约）。
- **依赖**：A1（BEV 定版）、A2（omni 轨迹）。

## B. 模型搭建（双脑按我们的架构）

### B1 ★ 拍板任务条件形式
- **做什么**：定 VLM→快脑的注入形式：**离散语义任务集**（推荐起步，5~10 类，抗幻觉省数据）vs **语言 embedding**（更灵活、要更多数据+改解码器）。
- **为什么**：决定 VLM 输出格式 + 快脑解码器怎么改怎么重训。
- **产出**：一句话定版 + 任务集/embedding 规格。
- **依赖**：慢脑验证（✅已完成）。**建议：离散语义集起步**，跑通后再上 embedding。

### B2 定我们的语义任务词表
- **做什么**：从慢脑验证的自拟任务收敛出标准词表，例如：`直行巡航 / 靠近设备巡检 / 岔路选向 / 靠近阀门查看 / 接近出口 / 降质暂停`。
- **为什么**：离散集需要固定 id；也是数据标注和 VLM 输出解析的依据。
- **产出**：`task_vocab.py`（id↔名称 + VLM 输出→id 的解析）。
- **依赖**：B1。

### B3 ★ 改 DiffusionDrive 解码器：加 VLM 任务条件注入通路
- **做什么**：在迁移版模型里，除原「BEV+ego」外，**多加一路任务条件**（离散 id embedding 或语言 embedding）注入级联解码器。**这是项目的论文级创新点**。
- **为什么**：学长 ckpt 只有 4 运动模式槽，喂不进我们的语义条件；必须新增通路。
- **产出**：改动后的 `V2TransfuserModel`（vendored 副本改，不动学长目录）。
- **依赖**：B1/B2。

### B4 重聚类 anchor（巡检运动学）
- **做什么**：用我们巡检轨迹（差速/原地转/omni）重跑 kmeans 出新 anchor（替 `kmeans_navsim_traj_20.npy`）。
- **为什么**：车端 anchor 不含原地转/横移，机器人动力学不同。
- **产出**：`anchors_inspect.npy`。
- **依赖**：A5（有轨迹数据）。

### B5 ★ 重训快脑
- **做什么**：用【我们的 BEV(±4~6m/ego/干净) + VLM 语义任务条件 + 真值轨迹标签 + 新 anchor】重训 DiffusionDrive。
- **为什么**：消除 domain gap + 让快脑真正"按任务选轨迹"。
- **产出**：新 ckpt 替换 `arch_e2e/weights/`（学长烟雾版退役）。
- **依赖**：A1、A5、B2、B3、B4。

### B6 双脑接通（闭环）
- **做什么**：Stage B / 闭环里把 `mode_onehot_for_ckpt` 换成**真 VLM 慢脑**：VLM 出语义任务 → 注入重训后的快脑。
- **为什么**：这才是完整双脑（慢脑认场景 → 快脑按任务出轨迹）。
- **产出**：完整双脑闭环 demo + 指标。
- **依赖**：A3、A4、B5。

### B7 端侧化（后续）
- **做什么**：VLM 量化上 Orin（或 API）、快脑 Orin 部署对齐；双脑延迟用低频慢脑+高频快脑掩盖。
- **依赖**：B6 跑通。

# 真机部署方案 v2：渐进式部署（2026-09-01）

> 升级自 `真机部署方案_0819.md`（v1 的拓扑/接口事实表/安全红线全部仍然有效，本文不重复，只写增量）。
> 核心变化：部署叙事从"先人工采集建图→再部署"升级为**三层渐进式**——到场即跑（无图VLN）→ 后台自主首探+自动建图 → 热切换完整模式（RELOC+cm级对接）。
> 动机：业界无图派（DualVLN/NaVILA/VLFM）即插即用但只做米级"到达/找物"；有图派做cm级但都要先建图。我们的卖点=**精度随建图渐进升级**，两头都占。

---

## 1. 三层部署模式总览

| | **M0 无图VLN模式** | **M1 首探建图中** | **M2 完整模式** |
|---|---|---|---|
| 前置条件 | 零（插电即跑） | M0在跑 | 地图资产就绪 |
| 导航能力 | VLM慢脑找目标 + 快脑VLN跟随 + frontier探索 | 同M0 | A*全局规划 + 站坐标直达 |
| 定位 | 指令积分（会漂，无纠偏） | 同M0，但采集的位姿被记录 | RELOC周期纠偏（每~2m拉回真值） |
| 对接精度 | 目标相对（zed深度+局部几何，**不依赖图**） | 同M0 | 绝对+相对双重（cm级落盘可复核） |
| 局限 | 无覆盖保证/回原位漂/长期漂移无解 | 同左 | 无（完整能力） |
| 对应ckpt | R2R快脑（goalnav_r2r_dense.pt系） | 同M0 | lab/走廊ckpt（goalnav_gate_lab.pt系） |

**切换逻辑**：M0进场即跑；状态机检测到"探索覆盖足够+采集帧数达标"→ 触发服务器 `auto_map_pipeline.sh`；流水线产出 `sim_world_<s>.npz + occ_bev + targets` 并校验通过 → 状态机热切换 M2（targets json 已在Orin上，ckpt常驻，切换=换配置不换进程）。

**物理约束（论文里要明写）**：cm级绝对精度必须锚定度量参考，无图模式下不存在绝对定位——这不是算法缺陷。M0的对接精度来自**目标相对定位**（DOCK本就只用zed深度+局部几何+正脸检测，全程不查全局图）。

## 2. M0 无图VLN模式（依赖：R2R快脑重训，进行中）

组成：ZED RGB → VLM慢脑（HTTP，自研10.0.0.18或服务器Qwen）→ 语义目标/探索决策 → R2R快脑（RGB+BEV+goal_ego status → 轨迹）→ 控制器 → Twist。

- **快脑**：用 R2R 链训出的 ckpt（吃 RGB + 局部BEV + goal_ego），天然无图——BEV 由 zed 深度实时反投影生成（同 run_diffusiondrive_policy 先例的 `points_to_bev_tensor`，不需要世界ply）。
- **慢脑**：纯 HTTP 客户端，零移植。confirm 用真图（铁律）。
- **探索**：frontier 模块（§4），M0 的"找目标"= 探索 + VLM逐帧确认。
- **DOCK**：局部对接链（min(zed深度,几何dist)伺服+正脸对齐）不依赖地图，M0即可用——这是"无图也能cm级贴脸"的关键。
- **做不到**：保证覆盖、回原位（漂移）、多站任务的站间复访精度。

## 3. M2 完整模式（=0819版全部内容）

A* 全局规划 / targets站坐标 / RELOC周期纠偏+到站纠偏 / ALIGN-DOCK / confirm审计。
0819版 §3.2 的两个输入gap（status 8维、BEV范围）注意：**M0/M2用的快脑ckpt不同，特征构造要按各自ckpt的输入定义做两份**——这份gap改造等R2R快脑定型后一次做对，避免返工。

## 4. M1 自主首探 + 自动建图流水线

### 4.1 Orin端：首探采集（边导航边录）

- frontier探索驱动（§5），同时按触发条件落盘采集：`images/zed/*.jpg` + `pointcloud/zed/*.npz`（xyzrgba mm）+ 指令积分位姿log。**目录布局必须与现有 `data/<session>/` 约定一致**（建图链脚本硬编码此布局）。
- 采集触发：间隔0.3m或15°取一帧（同仿真采集经验），首探结束时整体打包回传服务器（rsync，几GB级）。
- **cam_height 在采集前必须实测录入**（ZED离地高度，卷尺量）——这是全局尺度锚，量错=继承0.70×尺度债。

### 4.2 服务器端：auto_map_pipeline.sh（无人值守）

收齐数据后自动跑（阶段契约=outputs/命名约定，断点续跑=产物存在即跳过）：

```
data/<s> → _recon_single_cam_seq.py      COLMAP(sequential匹配,O(n),单相机)
         → build_colmap_session.py       导出vggto_<s>(cameras.npz+recon.ply+frames)
         → train_3dgs_vggt.py            3DGS(DEPTH_SUP=1深度监督+APPEARANCE)
         → align_gs_world.py --cam_height $MEASURED  重力对齐+米制+地面z=0 [--crop --untwist]
         → fit_world_geometry.py         墙/障碍拟合
         → occupancy_bev.py              烘2D占据栅格npz(Orin裁窗用)
         → build_nav_ds.py               位姿→真帧索引
         → (半自动) 场景图cg三步 + targets生成
```

每阶段落盘 VERDICT/日志，失败即停并报阶段号。校验点：COLMAP注册率（<80%报警）、模型数=1、align后cam_height回写npz、占据栅格png目检（回传缩略图给人确认）。

### 4.3 已知缺口（流水线里的半手工环节，按优先级）

1. **targets json 端到端生成**——当前是"zed深度定位+PCA/LSD求front+人工核对渲染图"半手工流程，散落在一次性操作里。**这是从地图到可执行任务之间的最大缺口**，需要固化成 `scripts/gen_targets_auto.py`（几何候选→VLM yes/no→front检测→json， lab_locate_clusters.py 已是雏形）。
2. **场景图第3步**（cfslam建图本体）要进 third_party/concept-graphs 手工跑，cg_prep/extract硬编码session名，需泛化封装。
3. **二次扶平**（apply_untwist/apply_zlevel）是110744硬编码一次性脚本，新场景若roll漂移>3°需仿写泛化版。

## 5. frontier 自主探索模块（设计，仿真先行）

**位置**：M0/M1的决策层，替代"任务状态机"成为无图时的慢脑执行器。
**输入**：zed深度→在线占据栅格（ego系累积，指令积分位姿拼接，接受漂移——探索只需要局部一致性）；VLM yes/no（"看到<target>了吗"）。
**循环**（VLFM式，参考 bdaiinstitute/vlfm MIT开源）：
1. 占据栅格提 frontier（自由/未知边界连通域，cv2 即可，别手搓复杂版）
2. frontier打分：距离代价 + VLM价值（接近目标语义的方向加分，M0找目标时）或 覆盖增益（M1建图时，朝未知多/视角多样的frontier加分）
3. 选最优frontier→快脑goal_ego→执行→新观测融入栅格
4. 死胡同回退：frontier耗尽回最近未访问分支（骨架DFS经验可复用，0803）
**终止**：目标confirm（M0）或 覆盖率>阈值+帧数达标（M1）→ 触发建图流水线。
**验证路径**：先在 test_env/仿真走廊实现并调通（零真机风险），再移植Orin。
**采集质量约束**：frontier打分加"沿墙/对设备视角多样性"项——采集是绕看式还是穿行式直接决定重建天花板（0720教训）。

## 7. 风险（v1风险仍有效，新增三条）

1. **M0/M2快脑双ckpt特征构造**——两份输入定义别混，改造前等R2R版定型。
2. **首探采集质量**——探索策略若只顾覆盖不顾视角多样性，重建会糊（采集天花板不可逆，只能重采）。frontier打分必须带视角项，且采集密度≥历史成功场景（510帧/18×12m）。
3. **无图漂移期间的绝对误差无界**——M0只承诺目标相对精度，论文/交付里都别over-claim绝对精度。
4. （v1遗留）reloc_server常驻GPU4与训练抢卡——加看门狗。

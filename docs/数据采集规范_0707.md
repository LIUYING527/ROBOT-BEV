# 数据采集规范 —— 需要采什么、现在缺什么、该怎么采

> 更新 2026/07/07。面向机器人控制/采集团队。从当前机器人代码（`robot_control_current/`）出发，说清：
> 1. **每样数据是干嘛用的**（下游：轨迹模型训练 / BEV / 三维重建）；
> 2. **现在机器人到底采没采上**（对到代码）；
> 3. **缺的怎么补、要改哪些机器人代码、什么格式**。
>
> 涉及代码：`robot_control_current/src/{camera_driver, web_control, chassis_control}`。

---

## 一、全局总表：谁要 → 用途 → 现状 → 缺口

| 用途 | 需要的数据 | 干嘛用 | 当前采集现状（代码实证） | 缺口/动作 |
|---|---|---|---|---|
| 模型训练 | `images/zed/*.jpg` | 相机输入 | ✅ `server.py` 2Hz 存 JPEG | 够用 |
| 模型训练 / BEV | `pointcloud/zed/*.npz` | 俯视点云 → BEV 栅格 | ✅ 存 `xyzrgba` 度量 mm | ⚠️ 只有**前向锥**（见 D） |
| 模型训练 | **自车轨迹 GT** | 未来轨迹标签 | ⚠️ 只有 `svtrobot_cmd`(**指令**)积分 | ❌ **最大缺口**：无 odom/位姿（见 C） |
| BEV 质量 | 环视/横向点云 | BEV 填满、非前向锥 | ❌ 单前视单程 | ❌ 绕拍协议（见 D） |
| 闭环 / BEV 对齐 | 自车位姿流 | ego 对齐、跟踪反馈 | ❌ 无 /odom（实测轮速仅 10s 刷） | ❌ 轮式+IMU 里程计（见 C） |
| 三维重建 / 皮肤 | 多视角 + 锁曝光 + 内参 + `.svo` | 场景重建、真实感渲染 | ⚠️ 前视/自动曝光/内参埋 rosbag/无 .svo | ❌ 见 D/E/G |

> 一句话：**图像和度量点云采得挺好，真正欠的是「自车准确轨迹/位姿」和「横向覆盖」这两样——它们不是文件格式问题，是采集时根本没产生这个信号。**

## 二、逐项详解（用途 / 现状 / 为什么之前没采上 / 怎么采 / 格式）

### A. 相机 RGB
- **用途**：轨迹模型的相机输入（训练时裁剪拼接 resize 到 3×256×1024）；也是重建/渲染的图源。
- **现状**：✅ `zed_camera.py` SDK 取左目（缺 SDK 时降级 OpenCV）；`server.py` 2Hz 存 `images/zed/*.jpg`（1280×720，文件名=时间戳 us），右目存 `images/zed_right/`。
- **格式**：JPEG，**文件名=纯数字时间戳**。
- **动作**：够用。原图分辨率越高越好（后续会 resize）。

### B. 度量点云 —— BEV 的来源
- **用途**：点云投成**俯视 2D 直方图**（数每格点数）→ 256×256 BEV 栅格喂模型。**BEV 是点云数出来的，不是图像转的**。
- **现状**：✅ `server.py:1126` `np.savez(key='xyzrgba')`，度量 **mm**，float16，全分辨率 1280×720。
- **为什么效果受限**：ZED 单前视 → 点云是**正前方一个锥**（x 恒正、后方两侧全黑），覆盖远不如 360° 环视雷达。这是**覆盖问题**（见 D），不是格式问题。
- **格式**：npz，键 `xyzrgba`，`(H,W,4)`，前 3 通道 xyz（单位 mm）。
- **动作**：格式够用；覆盖靠 D 补。

### C. ⭐ 自车轨迹 / 位姿 —— 训练标签 + BEV 对齐（**历史最大缺口**）
- **用途**：① 训练标签——需要自车真实轨迹，切出"未来若干秒的路点"当预测目标；② 闭环/部署时 BEV 以自车为中心裁窗、轨迹跟踪的误差反馈都要位姿。
- **现状（代码实证）**：⚠️ 只有 `svtrobot_cmd.jsonl`（**下发的速度指令** vx/vy/wz）。**没有 /odom、ZED positional tracking 没开、没 .svo**；`/chassis/joint_states` 里轮速是**目标值非实测**，`/chassis/diagnostics.wheel_speeds_actual`（实测轮速）**仅 ~10s 刷一次**，编码器 `read_encoder_lr()` 根本没发布。
- **⭐ 为什么之前没采上**：训练只能拿 `svtrobot_cmd` 去积分——但**指令 ≠ 实际走的路**（打滑、延迟、舵角未到位时轮速被强制置 0）。所以"准确自车轨迹"从来没被真正采集，只有一个会漂的指令积分兜底。这就是"需要的没采上"的头号问题。
- **怎么采**（三选一，按性价比）：
  1. **轮式+IMU 里程计并发 `/odom`**：底盘已有实测舵角(100Hz)+ZED IMU(~15Hz)，写个节点做 4WS 正运动学+IMU 融合 → 发 `/odom` 并录进 rosbag。**最省事、最该做**。
  2. **提高实测轮速轮询频率**：`chassis_control.cpp` 里 `wheel_speed_decimation_`（现在 50 ≈ 10s 一刷）调高，拿真·轮速编码里程计。
  3. **开 ZED positional tracking + 录 `.svo`**：直接拿视觉惯性里程计 + 带尺度轨迹，还能省重建。
- **格式**：`/odom`(`nav_msgs/Odometry`) 录进 rosbag → 转出 `odom.jsonl`（带 `_timestamp_ns`）；或直接存 `poses.jsonl`：`{"_timestamp_ns","x","y","yaw"}`（世界系，米制）。

### D. ⭐ 横向 / 环视覆盖（**最贵的教训**）
- **用途**：BEV 要填满（非前向锥）；三维重建/渲染离开行进轨迹的视角不糊，需要从多个横向角度看过同一处。
- **现状**：❌ 采集就是遥控机器人**往前开一趟**，ZED 单前视。`server.py` 只是被动存流，**不约束怎么走**。
- **为什么之前没采上**：没有覆盖协议——单目前视单程是物理上限，后处理/调参救不回来（本项目十几个重建实验证实）。
- **怎么采**（这是**操作动作规范**，不是代码）：
  - 重点目标（机柜/阀门/水泵）**减速 + 侧身/绕半圈拍**，多横向角度看同一物；
  - 走廊**走回环**（回到同一地点才能闭环）+ 有意**左右扫视**积累横向点；
  - 有条件加**侧视/后视相机**或云台**转头**，从根上补横向覆盖。
- **格式**：无新格式，产出仍是 A/B；关键在**走位轨迹**。

### E. 曝光 —— 治重建"白雾"
- **用途**：避免局部高光饱和导致信息永久丢失（过曝区重建后一片白雾，无法恢复）。
- **现状**：❌ `zed_camera.py` 用 SDK 默认（自动曝光），**没暴露曝光参数**。
- **怎么采**：在 `zed_camera.py` 暴露 `sl.VIDEO_SETTINGS.EXPOSURE/GAIN/AEC_AGC`，Web 端可配；**锁定/手动曝光**，逆光强光区降曝光或包围曝光；**宁欠勿过**（欠曝可后期提亮，过曝死白不可逆）。
- **格式**：无新文件；建议把曝光参数记进 `summary.json` 备查。

### F. 相机内参 + `.svo` —— 重建
- **用途**：内参用于去畸变/投影/重建；`.svo` 是 ZED 原始录制，回放能重取任意数据 + 带尺度轨迹。
- **现状**：⚠️ `zed_node.py` 发 `camera_info` 到 rosbag，但**录制不存独立内参文件**；**从不存 .svo**（找不到 .svo 是上一批数据的坑）。
- **怎么采**：① 录制时把内参 dump 成 `intrinsics.json`（图像走文件、内参别只埋 rosbag）；② `zed_camera.py` 开 `enable_recording()` 存 `.svo`。
- **格式**：`intrinsics.json`(fx,fy,cx,cy,distortion,baseline)；`recording.svo`。

### G. IMU / 时间戳同源
- **用途**：重力对齐、朝向、里程计融合（见 C）。
- **现状**：✅ ZED IMU `get_imu_data()` → `imu.jsonl`（~15Hz，随 grab；accel/gyro/mag/pressure/temp），不走 rosbag。
- **⚠️ 命脉：时间戳同源**——图像/点云靠**文件名时间戳**与指令对齐（对齐容差图像 150ms、点云 500ms）；各流必须同一时钟，否则对不齐、样本被丢。
- **格式**：`imu.jsonl` 每行含 `_timestamp_ns`。

## 三、目录与格式（训练预处理期望的固定布局，缺关键项即报错）

每次采集 = 一个文件夹 `<recording>/`（命名 `YYYYMMDD_HHMMSS`）：

```
<recording>/
├── svtrobot_cmd.jsonl          # ⭐ 指令(vx,vy,wz)  → 目前的轨迹来源(应升级为 odom, 见 C)
├── images/zed/*.jpg            # ⭐ 左目RGB, 名=时间戳us  → 相机输入
├── images/zed_right/*.jpg      #    右目
├── pointcloud/zed/*.npz        # ⭐ 度量点云(键 xyzrgba, mm) → BEV
├── depth/zed/*.jpg             #    ⚠️有损JET可视化(度量深度在点云里, 别拿这个当depth)
├── imu.jsonl                   #    ZED IMU ~15Hz
├── chassis_joint_states.jsonl  #    舵角实测 + 轮速目标
├── chassis_diagnostics.jsonl   #    实测轮速(~10s刷) / 温度 / 电压
├── f710_joy.jsonl / lift_control_cmd.jsonl
├── odom.jsonl / intrinsics.json / recording.svo   # ❌ 现在没有, 建议补(见 C/F)
├── summary.json
└── rosbag/rosbag_0.db3         # 原始bag(cmd/lift/joy/joint_states/diagnostics; 图像/点云/IMU走文件不进bag)
```

**关键文件内部格式**：

| 文件 | 关键字段 |
|---|---|
| `svtrobot_cmd.jsonl` | `{"linear":{x,y,z},"angular":{x,y,z},"_timestamp_ns"}`（取 x=vx, y=vy, angular.z=wz） |
| `images/zed/*.jpg` | 文件名=纯数字时间戳 |
| `pointcloud/zed/*.npz` | 键 `xyzrgba`，前 3 通道 xyz，单位 mm |

## 四、采集参数约束（满足训练需求）

| 项 | 值 | 对采集的含义 |
|---|---|---|
| 采样率 | ≥ 2Hz | 训练每秒抽 2 样本 → 原始 ≥6~10Hz 留挑帧余量（ZED 15fps 够） |
| 轨迹连续性 | 每段 ≥ 数十秒 | 每样本要"未来 4s"轨迹 → 单段**连续不中断** |
| 时间戳 | 同源时钟 | 图像/点云/指令按时间戳对齐（容差 150/500ms） |
| 点云单位 | mm | 训练侧会自动换算，采集端统一即可 |
| 深度 | 必须有点云 | 无点云的帧会被丢弃 |

## 五、要改机器人代码的清单（把缺口落到具体文件）

| 缺口 | 改哪里 | 做什么 |
|---|---|---|
| C 自车位姿 | 新节点 / `chassis_control` | 4WS 正运动学+IMU → 发 `/odom` 并录；或提高 `wheel_speed_decimation_` 频率 |
| E 曝光 | `camera_driver/zed_camera.py` | 暴露 EXPOSURE/GAIN/AEC_AGC，Web 可配，支持锁曝光 |
| F 内参/.svo | `zed_camera.py` / `server.py` | dump `intrinsics.json`；`enable_recording()` 存 `.svo` |
| depth 度量 | `web_control/server.py` | 如需度量深度图，存 16-bit PNG（现在只存有损 JET）；否则用点云即可 |

## 六、采集前 Checklist

- [ ] **走位**：重点目标减速+绕拍/侧身；走廊走回环+左右扫视（补横向视角 D）
- [ ] **曝光**：锁定/手动，逆光区降曝光（防白雾 E）
- [ ] **位姿**：确认 `/odom`（或 .svo/positional tracking）在录（否则轨迹只剩会漂的指令积分 C）
- [ ] **内参**：`intrinsics.json` 已 dump（F）
- [ ] **同源时钟**：各流时间戳同源（G）
- [ ] **连续性**：单段连续 ≥ 数十秒不中断
- [ ] **运动**：匀速慢行、转弯更慢（防运动模糊）
